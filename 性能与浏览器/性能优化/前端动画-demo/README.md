# 前端动画性能 Demo

对应 [前端动画.md](../前端动画.md)，四个面板各映射一道高频题，全部真实浏览器行为，单文件无依赖。

## 运行

浏览器直接打开 `index.html`。

## 面板与答题映射

| 面板 | 对应题 | 演示点 |
| --- | --- | --- |
| ① transform vs left | Q2/Q5 | 主线程阻塞时，合成器线程动画继续、rAF 动画冻结 |
| ② 强制同步布局 | Q7 | 读写交替 vs 批量读写，`performance.now()` 实测耗时 |
| ③ will-change / 合成层 | Q3/Q4 | 勾选后元素被提前提升为合成层（需 DevTools 验证） |
| ④ IntersectionObserver | Q10 | 卡片滚动进视口才触发 `animate-in`，只触发一次 |

## 真实 / 模拟边界（面试别混淆）

**真实（浏览器原生行为，可在本页直接观察）**：

- ① 的「阻塞主线程 → 绿盒动、蓝盒停」是**真实线程分离**——CSS `transform` 动画跑在合成器线程，rAF `left` 动画跑在主线程。
- ② 的耗时差是**真实测量**（`performance.now()`），读写交替确实会逐次触发强制同步布局。
- ④ 的进入视口触发是真实 `IntersectionObserver` 行为。

**不可见（需 DevTools，属于「验证手段」而非「页面渲染」）**：

- ③ 的「合成层」本身**无法在页面上可视化**——需要 DevTools → ⋮ → More tools → Rendering → 勾选 **Layer borders**（合成层显示橙色边框），或打开 **Layers** 面板查看分层。
- 「隐式合成 / 层爆炸」同样只能通过 Layers 面板观察（多层叠元素被同时提升），本 demo 未复现，仅在文档 Q3 讲解。

**不是真实测量（注意措辞）**：

- ① 的 FPS 计数器由主线程 rAF 采样，**只能反映主线程帧率**；它无法直接测量合成器线程动画的帧率（那本就跑在另一条线程）。绿盒流畅度以肉眼为准。
