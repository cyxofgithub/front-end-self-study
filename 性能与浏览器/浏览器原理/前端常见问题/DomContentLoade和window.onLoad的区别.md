## DOMContentLoaded vs window.onload 核心对比表

| 对比维度         | DOMContentLoaded                                                                  | window.onload                                                                              |
| ---------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **触发时机**     | HTML 解析完成 → DOM 树构建完毕 → 同步脚本执行完成                                 | DOM 树构建完成 + 所有外部资源（图片/视频/CSS/字体等）加载完毕                              |
| **等待资源**     | 不等待图片、CSS、字体等外部资源                                                   | 等待页面所有资源（包括图片、视频、第三方资源）加载完成                                     |
| **触发顺序**     | 先触发（页面加载流程中更早）                                                      | 后触发（页面加载流程中更晚）                                                               |
| **核心特点**     | 触发早，提升页面交互响应速度                                                      | 触发晚，确保所有资源可用                                                                   |
| **典型使用场景** | 1. 绑定 DOM 元素事件（点击/输入等）<br>2. 修改 DOM 文本/样式<br>3. 初始化表单逻辑 | 1. 获取图片真实尺寸/视频时长<br>2. 操作依赖外部资源的插件<br>3. 读取已加载的第三方资源数据 |
| **事件绑定方式** | `document.addEventListener('DOMContentLoaded', fn)`                               | `window.onload = fn` 或 `window.addEventListener('load', fn)`                              |

### 补充说明

-   如果页面没有任何外部资源（纯文本+HTML），二者触发时间会非常接近，但 `DOMContentLoaded` 仍会略早；
-   若页面有大图片/慢加载资源，`window.onload` 会比 `DOMContentLoaded` 晚很多（差距取决于资源加载速度）。
-   `window.onload`资源加载完成的判断取决于首页 html 所声明的资源加载完成（不包括懒加载）

### 总结

1. **核心区分**：`DOMContentLoaded` 只关注“DOM 结构可用”，`window.onload` 关注“所有资源可用”。
2. **使用原则**：DOM 操作优先用 `DOMContentLoaded`，依赖外部资源时才用 `window.onload`。
3. **顺序不变**：无论页面资源多少，`DOMContentLoaded` 永远先于 `window.onload` 触发。
