# Mini 实现：源码保真规则

## 适用范围

- 适用于手写框架源码的教学/练习实现：mini-react、mini-vue，以及任何「复刻框架原理」性质的代码（不限目录名）。
- 企业级业务示例不适用（那归 `code-rule` 管）。

## 核心原则：对齐什么

- **数据结构与存储方式跟源码**：如 React 的 DOM→Fiber 用节点 expando 属性（`node[internalInstanceKey]`），不自创 WeakMap 等替代存储。
- **关键时机跟源码**：登记在 createInstance/commitUpdate 等源码位置，不自选 appendChild 等时机。
- **模块划分与命名跟源码**：如 `eventSystem.js` ↔ `DOMPluginEventSystem.js`，便于源码↔实现互相索引。
- **API 形状跟源码**：函数名、参数顺序、返回值与源码一致，让真实框架的心智模型可以直接套用。

## 允许的简化

- 删兼容分支：IE 支持旧浏览器特性检测、多环境 fallback。
- 删可选特性：优先级 lanes、Suspense、并发特性、hydration 等。
- 删性能优化层：事件池、批量缓存等纯优化机制。
- 等价微优化换直白实现：可用更易懂的写法，但注释注明源码原做法。

## 禁止的简化

- **不得替换源码的核心数据结构**：「换存储/换结构」（如 WeakMap 换 expando）不是简化，是偏离。
- **不得改变登记/触发/提交等关键时机**：时机本身就是原理的一部分。
- **不得自创源码中不存在的中间层**：多一层抽象就多一处与源码对不上的心智负担。

## 偏离时要求（软约束）

- 确有理由偏离时，在代码处用 1 句注释注明「源码原做法 + 此处偏离原因」。
- 同步在项目 docs 的「与源码差异」表中登记该偏离。

## 输出要求

- 新增/修改 mini 实现后，同步维护项目内「与 X 源码的对应关系」表。
- 差异表有变动时一并更新，保证文档与实现一致。
