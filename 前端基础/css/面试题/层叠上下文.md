# CSS 层叠上下文（Stacking Context）

## 一、什么是层叠上下文

浏览器渲染页面时，元素是**三维**的：x轴水平、y轴垂直、**z轴垂直屏幕**。
z轴决定元素谁在上、谁在下，管理z轴层级的一套独立“层级容器”，就叫**层叠上下文**。

## 二、如何创建层叠上下文（触发条件）

满足任意一条，该元素就生成独立层叠上下文：

1. 根元素 `<html>`，天生根层叠上下文
2. `position: relative / absolute / fixed / sticky` 且 `z-index != auto`（必须设数字）
3. `opacity < 1`（透明度小于1）
4. `transform` 不为 `none`（平移、旋转、缩放等）
5. `filter` 不为 `none`
6. `will-change` 设 transform / opacity
7. `perspective` 不为 none
8. `mask / mask-image` 不为 none
9. `isolation: isolate` 强制创建

## 三、层叠顺序（同一层叠上下文内，从小到大，靠后在上）

同一层叠上下文里，元素按以下顺序从下到上堆叠：

1. **层叠上下文自身的背景、边框**（最底层）
2. 负z-index子元素 `z-index < 0`
3. 普通流内非定位元素（block、inline）
4. 浮动元素 float
5. 普通流内行内元素 inline/inline-block
6. `z-index:auto` / `z-index:0` 的定位元素
7. 正z-index子元素 `z-index > 0`（最上层）

### 极简记忆

负z < 普通文档流 < 浮动 < 行内元素 < z-index:0定位 < 正z

## 四、核心规则（重中之重）

1. **z-index 只在同一个层叠上下文内对比有效**
   不在同一个层叠上下文的两个元素，z-index再大也没用。
   例：
    - A容器：层叠上下文，z-index=1
    - A内部子元素：z-index=9999
    - B容器：同级元素，层叠上下文，z-index=2
      结果：B一定盖过A以及A里z-index:9999的子元素，因为父上下文层级更低。

2. 层叠上下文相互隔离，子元素无法突破父上下文的层级限制。
3. 不生成层叠上下文的定位元素，z-index仅在父层叠上下文参与排序。

## 五、经典示例演示

```html
<div class="box1" style="position:relative;z-index:1;transform:scale(1)">
    <!-- transform触发层叠上下文 -->
    <div
        style="position:absolute;z-index:9999;width:100px;height:100px;background:red;"
    ></div>
</div>
<div
    class="box2"
    style="position:relative;z-index:2;width:100px;height:100px;background:blue;"
></div>
```

蓝色box2会盖住红色9999，因为父box1层叠上下文z-index=1 < box2的2。

## 六、常见踩坑场景

1. 子元素z-index很大，却盖不住隔壁元素
   原因：父元素生成了层叠上下文，父z-index太低。
2. opacity设0.9后，内部定位元素层级异常
   opacity<1自动创建层叠上下文，限制内部z-index。
3. transform动画后弹窗被遮挡
   弹窗父容器有transform，生成独立上下文，弹窗再高z-index也出不去。

## 七、解决遮挡问题通用方案

1. 把弹窗放到**根html下**，脱离有transform/opacity的父容器
2. 给弹窗父层叠上下文提高z-index
3. 不需要动画的容器去掉transform、opacity等创建上下文属性
