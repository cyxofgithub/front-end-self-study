### 一、类型系统核心
1. **请解释 `any`、`unknown`、`never` 类型的区别及应用场景**
   - **考察点**：对 TypeScript 类型系统底层的理解
   - **答案要点**：
     - `any`：完全绕过类型检查，会污染类型系统，应尽量避免
     - `unknown`：类型安全的 `any`，需通过类型守卫/断言才能使用
     - `never`：永不存在的值的类型（如抛出错误、无限循环的函数返回类型）

2. **深入理解联合类型与交叉类型**
   - **考察点**：类型组合能力
   - **答案要点**：
     - 联合类型 `A | B`：值可以是其中一种类型
     - 交叉类型 `A & B`：值同时具有所有类型的属性
     - 结合类型守卫使用可实现类型安全的类型缩小

### 二、泛型与类型体操
3. **实现泛型工具类型 `DeepReadonly<T>`**
   - **考察点**：递归类型、映射类型的综合应用
   - **答案示例**：

     ```typescript
     // DeepReadonly<T>：让 T 的所有属性递归变为只读
     type DeepReadonly<T> = {
       // 对每个属性 P，加上 readonly
       readonly [P in keyof T]:
         // 如果值还是对象（注意可能包括数组、函数等）
         T[P] extends object
           // 则递归对 T[P] 再做 DeepReadonly
           ? DeepReadonly<T[P]>
           // 基础类型直接返回原值类型
           : T[P];
     };
     ```

**解释：**
     - 这个类型让你传进去任何对象类型，它会把里面每个属性都变成只读，并且如果属性本身还是对象也会递归处理。
     - 常见用法：用来生成深层不可变对象，避免误操作修改。
     - “extends object”这里注意，包括了数组和函数类型，如果想排除函数可进一步优化。

4. **泛型约束与条件类型的实际应用**
   - **考察点**：泛型的高级用法
   - **答案要点**：
     - 使用 `extends` 约束泛型类型范围
     - 条件类型 `T extends U ? X : Y` 实现类型选择
     - 结合 `infer` 关键字实现类型提取

   **示例：**

   ```typescript
   // 1. 泛型约束，限制 T 必须有 length 属性
   function getLength<T extends { length: number }>(input: T): number {
     return input.length;
   }

   // 2. 条件类型，判断类型是否为 string
   type IsString<T> = T extends string ? true : false;

   // 3. infer 提取 Promise 内的类型
   type UnPromisify<T> = T extends Promise<infer U> ? U : T;

   // 使用示例
   const len = getLength('hello'); // 返回 5
   type A = IsString<'abc'>; // true
   type B = UnPromisify<Promise<number>>; // number
   ```

   **说明：**
   - 泛型约束让函数或类型更安全，避免滥用。
   - 条件类型和 infer 能灵活实现类型分支与类型拆解，是构建工具类型的核心能力。

### 三、接口与类型别名
5. **`interface` 与 `type` 的区别及选型策略**

   > 一句话结论：两者都能描述对象和函数；`interface` 的核心优势是可扩展、可声明合并，`type` 的核心优势是能给任意类型表达式起别名。普通对象二者都可以，按是否需要开放扩展来选。

   | 对比项 | `interface` | `type` |
   | --- | --- | --- |
   | 对象、函数类型 | 支持 | 支持 |
   | 联合类型、元组、基本类型别名 | 不支持直接定义 | 支持 |
   | 扩展方式 | `extends` | 交叉类型 `&` |
   | 同名声明合并 | 支持 | 不支持，重复声明报错 |
   | 映射类型、条件类型 | 不能直接定义 | 支持 |
   | 类 `implements` | 支持 | 对象形状的 `type` 也支持；联合类型不支持 |

   **共同能力：描述对象和函数**

   ```typescript
   interface User {
     id: string;
     name: string;
   }

   type UserAlias = {
     id: string;
     name: string;
   };

   interface Formatter {
     (value: number): string;
   }

   type FormatterAlias = (value: number) => string;
   ```

   **`interface`：声明合并，适合开放扩展的公共契约**

   ```typescript
   interface WindowConfig {
     theme: 'light' | 'dark';
   }

   interface WindowConfig {
     locale: string;
   }

   // 同名声明自动合并，两个字段都必填
   const config: WindowConfig = {
     theme: 'dark',
     locale: 'zh-CN',
   };
   ```

   声明合并常用于扩展第三方库或全局类型，但业务内部也要避免无意重名。`type` 是封闭定义，同名声明会直接报错。

   **`type`：表达联合、元组、映射和条件类型**

   ```typescript
   type RequestStatus = 'idle' | 'loading' | 'success' | 'error';
   type Coordinate = readonly [x: number, y: number];
   type Nullable<T> = T | null;
   type ReadonlyModel<T> = {
     readonly [K in keyof T]: T[K];
   };
   type ApiResult<T> = T extends Error
     ? { ok: false; error: T }
     : { ok: true; data: T };
   ```

   **扩展时的差异：冲突发现时机不同**

   ```typescript
   interface WithStringId {
     id: string;
   }

   interface WithNumberId {
     id: number;
   }

   // interface Invalid extends WithStringId, WithNumberId {}
   // 直接报错：属性 id 不兼容

   type InvalidAlias = WithStringId & WithNumberId;
   // 不在定义处报错，但 id 会变成 never，实际无法正常赋值
   ```

   **选型建议：**

   - 对外暴露、希望使用方继续扩展的对象契约，例如组件 Props、SDK 模型，优先 `interface`。
   - 联合类型、元组、工具类型或需要复杂类型运算时，使用 `type`。
   - 普通内部对象类型二者能力接近，遵循团队规范并保持一致，不必为了“性能更好”强行选择某一个。

   **面试回答：**

   > `interface` 和 `type` 都能描述对象、函数，也都可以被类实现。主要区别是 `interface` 支持 `extends` 和同名声明合并，因此更适合可扩展的公共对象契约；`type` 可以表示联合、元组、基本类型别名，并能组合映射类型、条件类型，表达能力更广。扩展冲突时，`interface` 通常在定义处直接报错，而交叉类型可能把冲突属性变成 `never`。实际项目里，对外可扩展的对象 API 我倾向用 `interface`，复杂类型运算用 `type`，普通内部对象则跟随团队规范。

### 四、类型兼容性
6. **解释 TypeScript 中的协变与逆变**
   - **考察点**：类型系统的底层设计
   - **答案要点**：
     - 协变：子类型可赋值给父类型（如 `Dog[]` → `Animal[]`）
     - 逆变：父类型可赋值给子类型（如函数参数）
     - 开启 `strictFunctionTypes` 可获得更严格的类型检查

   **实际例子：**

   ```typescript
   class Animal {}
   class Dog extends Animal {}
   class Cat extends Animal {}

   // 协变示例：数组是协变的，Dog[]可以赋值给Animal[]
   const dogs: Dog[] = [new Dog()];
   const animals: Animal[] = dogs; // ✅ 协变成立

   // 逆变示例：函数参数类型是逆变的
   type Handler<T> = (arg: T) => void;

   let handleAnimal: Handler<Animal> = (a: Animal) => {};
   let handleDog: Handler<Dog> = (d: Dog) => {};

   handleAnimal = handleDog; // ❌ 如果 strictFunctionTypes 开启，逆变类型不允许赋值
   // 解释：handleDog 期望收到的参数是 Dog，但 handleAnimal 允许传任何 Animal，包含 Cat
   // 导致 handleDog 可能收到一个 Cat，类型不安全

   // 更直观验证（strictFunctionTypes下不允许）：
   function feedDog(dog: Dog) {}
   function feedAnimal(animal: Animal) {}

   // feedDog = feedAnimal; // ✅ 允许（逆变）
   // feedAnimal = feedDog; // ❌ 不安全
   ```

   **总结说明：**
   - 数组等协变结构，可以安全地将子类型数组赋值给父类型数组
   - 函数参数是逆变的，防止类型不安全（尤其是在 strictFunctionTypes 下）

### 五、装饰器与元编程
7. **实现一个类方法装饰器 `@log`**
   - **考察点**：装饰器的实际应用
   - **答案示例**：
     ```typescript
     function log(target: any, methodName: string, descriptor: PropertyDescriptor) {
       const original = descriptor.value;
       descriptor.value = function(...args: any[]) {
         console.log(`Calling ${methodName} with`, args);
         return original.apply(this, args);
       };
     }
     ```

### 七、框架结合（React 方向）
10. **React + TypeScript 最佳实践**
    - **考察点**：实际开发中的类型安全
    - **答案要点**：
