# Redis 基础知识

## 一、缓存三大问题

### 1. 缓存穿透（Cache Penetration）

#### 问题定义

缓存穿透是指查询一个**不存在的数据**，由于缓存中也没有，导致每次请求都会穿透到数据库，造成数据库压力过大。

#### 产生原因

-   恶意攻击：故意查询不存在的数据（如不存在的用户 ID、商品 ID）
-   业务逻辑问题：查询条件不合理，导致大量无效查询

#### 问题示例

```javascript
// 错误示例：没有处理数据不存在的情况
async function getUser(userId) {
    // 1. 先查缓存
    const cached = await redis.get(`user:${userId}`);
    if (cached) {
        return JSON.parse(cached);
    }

    // 2. 缓存未命中，查数据库
    const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);

    // 3. 如果用户不存在，没有缓存，下次还会查数据库
    if (user) {
        await redis.setEx(`user:${userId}`, 3600, JSON.stringify(user));
    }

    return user; // 返回 null
}
```

**问题**：当查询不存在的用户时，每次都会查询数据库，造成数据库压力。

#### 解决方案

**方案 1：缓存空值（推荐）**

```javascript
async function getUser(userId) {
    const cacheKey = `user:${userId}`;

    // 1. 先查缓存
    const cached = await redis.get(cacheKey);
    if (cached !== null) {
        // 注意：null 也会被缓存
        return cached === 'null' ? null : JSON.parse(cached);
    }

    // 2. 缓存未命中，查数据库
    const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);

    // 3. 防止缓存穿透：即使数据不存在也缓存空值
    if (user) {
        await redis.setEx(cacheKey, 3600, JSON.stringify(user));
    } else {
        // 缓存空值，设置较短的过期时间（如5分钟）
        await redis.setEx(cacheKey, 300, 'null');
    }

    return user;
}
```

**方案 2：布隆过滤器（Bloom Filter）**

布隆过滤器是一种**概率型数据结构**，用于快速判断一个元素是否**可能存在**于集合中。

**工作原理**：

-   使用多个哈希函数将元素映射到位数组（bit array）的多个位置
-   查询时，如果所有哈希位置都是 1，则元素**可能存在**；如果任一位置是 0，则元素**肯定不存在**
-   **特点**：
    -   ✅ 内存占用小，查询速度快（O(k)，k 为哈希函数个数）
    -   ✅ 不存在误判（如果返回不存在，则一定不存在）
    -   ⚠️ 存在误判率（如果返回存在，可能实际不存在，需要进一步验证）
    -   ⚠️ 不支持删除操作（可以使用变种 Counting Bloom Filter）

**适用场景**：ID 范围固定、需要快速过滤大量不存在数据的场景。

```javascript
const BloomFilter = require('bloom-filter');

// 初始化布隆过滤器（需要提前加载所有有效ID）
const bloomFilter = new BloomFilter(10000, 4); // 容量10000，哈希函数4个

// 预热：加载所有有效的用户ID
async function initBloomFilter() {
    const userIds = await db.query('SELECT id FROM users');
    userIds.forEach((user) => bloomFilter.add(user.id));
}

async function getUser(userId) {
    // 1. 先检查布隆过滤器
    if (!bloomFilter.contains(userId)) {
        return null; // 肯定不存在，直接返回
    }

    // 2. 布隆过滤器说可能存在，继续查缓存和数据库
    const cacheKey = `user:${userId}`;
    const cached = await redis.get(cacheKey);
    if (cached) {
        return JSON.parse(cached);
    }

    const user = await db.query('SELECT * FROM users WHERE id = ?', [userId]);
    if (user) {
        await redis.setEx(cacheKey, 3600, JSON.stringify(user));
    }

    return user;
}
```

#### 总结

| 方案       | 优点               | 缺点                 | 适用场景           |
| ---------- | ------------------ | -------------------- | ------------------ |
| 缓存空值   | 实现简单，效果明显 | 占用缓存空间         | 大多数场景（推荐） |
| 布隆过滤器 | 内存占用小，查询快 | 需要预热，有误判率   | ID 范围固定的场景  |
| 参数校验   | 简单直接           | 只能过滤明显无效请求 | 作为辅助手段       |

### 2. 缓存击穿（Cache Breakdown）

#### 问题定义

缓存击穿是指一个**热点 key** 在缓存过期的一瞬间，有大量并发请求同时查询这个 key，导致所有请求都打到数据库。

#### 产生原因

-   热点数据过期：某个访问量很大的 key 突然过期
-   没有预热：系统启动时热点数据未加载到缓存
-   并发量大：大量用户同时访问同一个资源

#### 问题示例

```javascript
// 错误示例：没有处理热点key失效的情况
async function getHotProduct(productId) {
    const cacheKey = `product:${productId}`;

    // 1. 查缓存
    const cached = await redis.get(cacheKey);
    if (cached) {
        return JSON.parse(cached);
    }

    // 2. 缓存失效，查数据库
    // 问题：如果这个商品是热点商品，此时可能有1000个并发请求同时执行到这里
    const product = await db.query('SELECT * FROM products WHERE id = ?', [
        productId,
    ]);

    if (product) {
        await redis.setEx(cacheKey, 3600, JSON.stringify(product));
    }

    return product;
}
```

**问题**：当热点 key 过期时，大量并发请求同时查询数据库，造成数据库压力瞬间飙升。

#### 解决方案

**方案 1：分布式锁（推荐）**

```javascript
async function getHotProduct(productId) {
    const cacheKey = `product:${productId}`;
    const lockKey = `lock:product:${productId}`;

    // 1. 先查缓存
    const cached = await redis.get(cacheKey);
    if (cached) {
        return JSON.parse(cached);
    }

    // 2. 缓存未命中，尝试获取分布式锁
    const lockAcquired = await redis.set(lockKey, 'locked', {
        EX: 10, // 10秒过期
        NX: true, // 只在key不存在时设置
    });

    if (lockAcquired) {
        // 3. 获取锁成功，查数据库并更新缓存
        try {
            // 双重检查：获取锁后再次检查缓存（可能其他线程已经更新了）
            const cachedAgain = await redis.get(cacheKey);
            if (cachedAgain) {
                return JSON.parse(cachedAgain);
            }

            const product = await db.query(
                'SELECT * FROM products WHERE id = ?',
                [productId]
            );

            if (product) {
                await redis.setEx(cacheKey, 3600, JSON.stringify(product));
            }

            return product;
        } finally {
            // 4. 释放锁
            await redis.del(lockKey);
        }
    } else {
        // 5. 获取锁失败，说明其他线程正在更新缓存，等待并重试
        await new Promise((resolve) => setTimeout(resolve, 100)); // 等待100ms
        return getHotProduct(productId); // 递归重试
    }
}
```

**方案 2：永不过期 + 异步更新**

```javascript
async function getHotProduct(productId) {
    const cacheKey = `product:${productId}`;
    const updateFlagKey = `update:product:${productId}`;

    // 1. 查缓存
    const cached = await redis.get(cacheKey);
    if (cached) {
        // 2. 检查是否需要更新（通过另一个key控制）
        const needUpdate = await redis.get(updateFlagKey);
        if (!needUpdate) {
            // 异步更新缓存（不阻塞当前请求）
            updateCacheAsync(productId).catch(console.error);
            await redis.setEx(updateFlagKey, 300, '1'); // 5分钟内只更新一次
        }
        return JSON.parse(cached);
    }

    // 3. 缓存不存在，查数据库
    const product = await db.query('SELECT * FROM products WHERE id = ?', [
        productId,
    ]);
    if (product) {
        // 设置永不过期的缓存
        await redis.set(cacheKey, JSON.stringify(product));
        await redis.setEx(updateFlagKey, 300, '1');
    }

    return product;
}

// 异步更新缓存
async function updateCacheAsync(productId) {
    const product = await db.query('SELECT * FROM products WHERE id = ?', [
        productId,
    ]);
    if (product) {
        await redis.set(`product:${productId}`, JSON.stringify(product));
    }
}
```

**方案 3：多级缓存**

```javascript
// 本地缓存（如 Node.js 的 Map）
const localCache = new Map();

async function getHotProduct(productId) {
    const cacheKey = `product:${productId}`;

    // 1. 先查本地缓存
    if (localCache.has(cacheKey)) {
        return localCache.get(cacheKey);
    }

    // 2. 查 Redis 缓存
    const cached = await redis.get(cacheKey);
    if (cached) {
        const product = JSON.parse(cached);
        localCache.set(cacheKey, product);
        // 本地缓存5分钟过期
        setTimeout(() => localCache.delete(cacheKey), 5 * 60 * 1000);
        return product;
    }

    // 3. 查数据库
    const product = await db.query('SELECT * FROM products WHERE id = ?', [
        productId,
    ]);
    if (product) {
        await redis.setEx(cacheKey, 3600, JSON.stringify(product));
        localCache.set(cacheKey, product);
        setTimeout(() => localCache.delete(cacheKey), 5 * 60 * 1000);
    }

    return product;
}
```

#### 总结

| 方案     | 优点                     | 缺点               | 适用场景             |
| -------- | ------------------------ | ------------------ | -------------------- |
| 分布式锁 | 保证只有一个线程查数据库 | 实现复杂，有锁竞争 | 热点数据场景（推荐） |
| 永不过期 | 避免缓存失效             | 数据可能不够新鲜   | 数据变化不频繁的场景 |
| 多级缓存 | 减少 Redis 压力          | 占用应用内存       | 超高并发场景         |

### 3. 缓存雪崩（Cache Avalanche）

#### 问题定义

缓存雪崩是指**大量缓存 key 同时过期**，导致大量请求同时打到数据库，造成数据库压力过大甚至宕机。

#### 产生原因

-   缓存过期时间设置相同：大量 key 设置了相同的过期时间
-   缓存服务宕机：Redis 服务不可用
-   系统启动：系统重启后缓存为空，大量请求打到数据库

#### 问题示例

```javascript
// 错误示例：所有商品缓存都设置相同的过期时间
async function getProducts() {
    const products = await db.query('SELECT * FROM products');

    // 问题：所有商品都设置1小时过期，1小时后同时失效
    products.forEach((product) => {
        redis.setEx(`product:${product.id}`, 3600, JSON.stringify(product));
    });

    return products;
}
```

**问题**：当大量 key 同时过期时，大量并发请求同时查询数据库，造成数据库压力瞬间飙升。

#### 解决方案

**方案 1：随机过期时间（推荐）**

```javascript
async function getProduct(productId) {
    const cacheKey = `product:${productId}`;

    // 1. 查缓存
    const cached = await redis.get(cacheKey);
    if (cached) {
        return JSON.parse(cached);
    }

    // 2. 查数据库
    const product = await db.query('SELECT * FROM products WHERE id = ?', [
        productId,
    ]);

    if (product) {
        // 设置随机过期时间：3600-4200秒（1小时 ± 10分钟）
        const ttl = 3600 + Math.floor(Math.random() * 600);
        await redis.setEx(cacheKey, ttl, JSON.stringify(product));
    }

    return product;
}
```

**方案 2：缓存预热**

```javascript
// 系统启动时预热热点数据
async function warmupCache() {
    // 1. 加载热点商品
    const hotProducts = await db.query(
        'SELECT * FROM products WHERE is_hot = 1 ORDER BY view_count DESC LIMIT 100'
    );

    // 2. 批量写入缓存，设置随机过期时间
    const pipeline = redis.pipeline();
    hotProducts.forEach((product) => {
        const ttl = 3600 + Math.floor(Math.random() * 600);
        pipeline.setEx(`product:${product.id}`, ttl, JSON.stringify(product));
    });
    await pipeline.exec();

    console.log(`预热了 ${hotProducts.length} 个热点商品`);
}
```

**方案 3：多级缓存 + 降级策略**

```javascript
async function getProduct(productId) {
    const cacheKey = `product:${productId}`;

    try {
        // 1. 查 Redis 缓存
        const cached = await redis.get(cacheKey);
        if (cached) {
            return JSON.parse(cached);
        }

        // 2. Redis 未命中，查数据库
        const product = await db.query('SELECT * FROM products WHERE id = ?', [
            productId,
        ]);

        if (product) {
            const ttl = 3600 + Math.floor(Math.random() * 600);
            await redis.setEx(cacheKey, ttl, JSON.stringify(product));
        }

        return product;
    } catch (error) {
        // 3. Redis 异常，降级到数据库
        console.error('Redis 异常，降级到数据库:', error);
        return await db.query('SELECT * FROM products WHERE id = ?', [
            productId,
        ]);
    }
}
```

| 方案         | 优点               | 缺点                 | 适用场景           |
| ------------ | ------------------ | -------------------- | ------------------ |
| 随机过期时间 | 实现简单，效果明显 | 需要合理设置随机范围 | 大多数场景（推荐） |
| 缓存预热     | 避免启动时压力     | 需要识别热点数据     | 系统启动时         |
| 多级缓存     | 提高可用性         | 实现复杂             | 高可用要求场景     |

## 二、Lua 脚本保证原子性

### 为什么需要 Lua 脚本？

Redis 虽然提供了原子操作（如 `INCR`、`DECR`），但在复杂业务场景中，往往需要**多个 Redis 命令组合执行**，而这些命令组合不是原子性的。

#### 问题示例

```javascript
// 错误示例：多个命令不是原子性的
async function reduceStock(productId, quantity) {
    const stockKey = `stock:${productId}`;

    // 1. 获取库存
    const stock = await redis.get(stockKey);
    if (!stock || parseInt(stock) < quantity) {
        throw new Error('库存不足');
    }

    // 2. 扣减库存
    await redis.decrBy(stockKey, quantity);

    // 问题：在步骤1和2之间，其他请求可能已经修改了库存，导致超卖
}
```

**问题**：在高并发场景下，多个命令之间可能被其他请求插入，导致数据不一致。

### Lua 脚本的优势

1. **原子性**：整个脚本作为一个原子操作执行，不会被其他命令打断
2. **减少网络开销**：多个命令在一个脚本中执行，减少网络往返
3. **复杂逻辑**：支持条件判断、循环等复杂逻辑

### Lua 脚本语法

#### 基本语法

```lua
-- Lua 脚本示例
local key = KEYS[1]        -- 获取第一个key
local value = ARGV[1]      -- 获取第一个参数
local result = redis.call('GET', key)  -- 调用Redis命令
return result              -- 返回结果
```

#### Redis 命令调用

```lua
-- 调用 Redis 命令
redis.call('SET', 'key', 'value')
redis.call('GET', 'key')
redis.call('INCR', 'key')
redis.call('DECR', 'key')
redis.call('EXPIRE', 'key', 3600)

-- 调用 Redis 命令（出错时返回错误，不抛出异常）
redis.pcall('SET', 'key', 'value')
```

### 实战案例

#### 案例 1：库存扣减（防止超卖）

```javascript
// Lua 脚本：原子性扣减库存
const reduceStockScript = `
  local stockKey = KEYS[1]
  local quantity = tonumber(ARGV[1])
  
  -- 获取当前库存
  local stock = redis.call('GET', stockKey)
  if not stock then
    return {-1, '库存信息不存在'}
  end
  
  stock = tonumber(stock)
  
  -- 检查库存是否充足
  if stock < quantity then
    return {0, '库存不足', stock}
  end
  
  -- 扣减库存
  local newStock = redis.call('DECRBY', stockKey, quantity)
  
  return {1, '扣减成功', newStock}
`;

// 使用 Lua 脚本
async function reduceStock(productId, quantity) {
    const stockKey = `stock:${productId}`;

    const result = await redis.eval(reduceStockScript, {
        keys: [stockKey],
        arguments: [quantity.toString()],
    });

    const [status, message, stock] = result;

    if (status === -1) {
        throw new Error('库存信息不存在');
    }
    if (status === 0) {
        throw new Error(`库存不足，当前库存：${stock}`);
    }

    return {
        success: true,
        message: message,
        remainingStock: stock,
    };
}
```

#### 案例 2：点赞/取消点赞（原子性操作）

```javascript
// Lua 脚本：原子性点赞/取消点赞
const toggleLikeScript = `
  local likeKey = KEYS[1]      -- 点赞集合 key
  local rankKey = KEYS[2]      -- 排行榜 key
  local articleId = ARGV[1]    -- 文章ID
  local userId = ARGV[2]       -- 用户ID
  
  -- 检查是否已点赞
  local isMember = redis.call('SISMEMBER', likeKey, userId)
  
  if isMember == 1 then
    -- 取消点赞
    redis.call('SREM', likeKey, userId)
    local count = redis.call('SCARD', likeKey)
    redis.call('ZADD', rankKey, count, articleId)
    return {0, count}  -- 0表示取消点赞
  else
    -- 点赞
    redis.call('SADD', likeKey, userId)
    local count = redis.call('SCARD', likeKey)
    redis.call('ZADD', rankKey, count, articleId)
    return {1, count}  -- 1表示点赞成功
  end
`;

// 使用 Lua 脚本
async function toggleLike(userId, articleId) {
    const likeKey = `article:like:${articleId}`;
    const rankKey = 'article:like:rank';

    const result = await redis.eval(toggleLikeScript, {
        keys: [likeKey, rankKey],
        arguments: [articleId.toString(), userId.toString()],
    });

    const [action, count] = result;

    return {
        action: action === 1 ? 'liked' : 'unliked',
        likeCount: count,
    };
}
```

#### 案例 3：秒杀操作（复杂业务逻辑）

```javascript
// Lua 脚本：原子性秒杀操作
const seckillScript = `
  local stockKey = KEYS[1]           -- 库存 key
  local purchasedKey = KEYS[2]       -- 已购买用户集合 key
  local resultKey = KEYS[3]          -- 结果 key
  local userId = ARGV[1]             -- 用户ID
  local activityId = ARGV[2]         -- 活动ID
  local timestamp = ARGV[3]          -- 时间戳
  
  -- 1. 检查是否已购买
  local isPurchased = redis.call('SISMEMBER', purchasedKey, userId)
  if isPurchased == 1 then
    return {0, '您已参与过此活动'}
  end
  
  -- 2. 检查库存
  local stock = redis.call('GET', stockKey)
  if not stock then
    return {-1, '活动不存在'}
  end
  
  stock = tonumber(stock)
  if stock <= 0 then
    -- 记录结果：已售罄
    redis.call('HSET', resultKey, 'status', 'sold_out', 'timestamp', timestamp)
    redis.call('EXPIRE', resultKey, 3600)
    return {1, '商品已售罄'}
  end
  
  -- 3. 扣减库存
  local newStock = redis.call('DECR', stockKey)
  
  -- 4. 记录已购买用户
  redis.call('SADD', purchasedKey, userId)
  
  -- 5. 记录结果：成功
  local orderId = 'SK' .. userId .. activityId .. timestamp
  redis.call('HSET', resultKey, 'status', 'success', 'orderId', orderId, 'timestamp', timestamp)
  redis.call('EXPIRE', resultKey, 3600)
  
  return {2, orderId, newStock}
`;

// 使用 Lua 脚本
async function seckill(userId, activityId) {
    const stockKey = `seckill:stock:${activityId}`;
    const purchasedKey = `seckill:purchased:${activityId}`;
    const resultKey = `seckill:result:${userId}:${activityId}`;

    const result = await redis.eval(seckillScript, {
        keys: [stockKey, purchasedKey, resultKey],
        arguments: [
            userId.toString(),
            activityId.toString(),
            Date.now().toString(),
        ],
    });

    const [status, message, data] = result;

    switch (status) {
        case 0:
            throw new Error(message); // 已购买
        case -1:
            throw new Error(message); // 活动不存在
        case 1:
            return { success: false, message }; // 已售罄
        case 2:
            return { success: true, orderId: message, remainingStock: data };
        default:
            throw new Error('未知错误');
    }
}
```

#### 案例 4：分布式锁（原子性加锁）

```javascript
// Lua 脚本：原子性加锁
const acquireLockScript = `
  local lockKey = KEYS[1]
  local lockValue = ARGV[1]
  local expireTime = tonumber(ARGV[2])
  
  -- 尝试加锁（SET key value EX seconds NX）
  local result = redis.call('SET', lockKey, lockValue, 'EX', expireTime, 'NX')
  
  if result then
    return 1  -- 加锁成功
  else
    return 0  -- 加锁失败
  end
`;

// Lua 脚本：原子性释放锁（检查锁的值是否匹配）
const releaseLockScript = `
  local lockKey = KEYS[1]
  local lockValue = ARGV[1]
  
  -- 获取锁的值
  local currentValue = redis.call('GET', lockKey)
  
  if currentValue == lockValue then
    -- 锁的值匹配，删除锁
    redis.call('DEL', lockKey)
    return 1  -- 释放成功
  else
    return 0  -- 释放失败（锁已被其他线程持有或已过期）
  end
`;

// 使用 Lua 脚本
class DistributedLock {
    constructor(redis, key, expireTime = 10) {
        this.redis = redis;
        this.key = key;
        this.expireTime = expireTime;
        this.value = `${Date.now()}-${Math.random()}`; // 唯一标识
    }

    async acquire() {
        const result = await this.redis.eval(acquireLockScript, {
            keys: [this.key],
            arguments: [this.value, this.expireTime.toString()],
        });
        return result === 1;
    }

    async release() {
        const result = await this.redis.eval(releaseLockScript, {
            keys: [this.key],
            arguments: [this.value],
        });
        return result === 1;
    }
}

// 使用示例
async function doSomethingWithLock() {
    const lock = new DistributedLock(redis, 'lock:resource:123', 10);

    if (await lock.acquire()) {
        try {
            // 执行业务逻辑
            console.log('获取锁成功，执行业务逻辑');
            await doBusinessLogic();
        } finally {
            await lock.release();
        }
    } else {
        throw new Error('获取锁失败');
    }
}
```

### Lua 脚本最佳实践

#### 1. 脚本应该简洁高效

```lua
-- ✅ 好的做法：简洁高效
local stock = redis.call('GET', KEYS[1])
if tonumber(stock) < tonumber(ARGV[1]) then
    return {0, '库存不足'}
end
return {1, redis.call('DECRBY', KEYS[1], ARGV[1])}

-- ❌ 不好的做法：过于复杂，可能阻塞 Redis
for i = 1, 10000 do
    redis.call('GET', 'key' .. i)
end
```

#### 2. 使用 `tonumber()` 转换数字

```lua
-- ✅ 好的做法：显式转换
local stock = tonumber(redis.call('GET', KEYS[1]))
local quantity = tonumber(ARGV[1])

-- ❌ 不好的做法：直接比较字符串
local stock = redis.call('GET', KEYS[1])
if stock < ARGV[1] then  -- 可能出错
    return {0, '库存不足'}
end
```

#### 3. 错误处理

```lua
-- ✅ 好的做法：检查返回值
local stock = redis.call('GET', KEYS[1])
if not stock then
    return {-1, '库存信息不存在'}
end

-- ❌ 不好的做法：不检查返回值
local stock = redis.call('GET', KEYS[1])
local newStock = stock - tonumber(ARGV[1])  -- stock 可能是 nil，会报错
```

#### 4. 使用 `redis.pcall()` 处理错误

```lua
-- ✅ 好的做法：使用 pcall 处理可能出错的命令
local result = redis.pcall('GET', KEYS[1])
if result['err'] then
    return {-1, '获取库存失败'}
end

-- ❌ 不好的做法：使用 call，出错会中断脚本
local result = redis.call('GET', KEYS[1])  -- 如果 key 不存在，会返回 nil，但如果是其他错误会中断
```

#### 5. 避免在脚本中执行耗时操作

```lua
-- ❌ 不好的做法：在脚本中执行耗时操作
local result = {}
for i = 1, 10000 do
    result[i] = redis.call('GET', 'key' .. i)
end
return result

-- ✅ 好的做法：使用 pipeline 或批量操作
-- 在应用层使用 pipeline，而不是在 Lua 脚本中循环
```

### Lua 脚本 vs Redis 事务

| 特性     | Lua 脚本                | Redis 事务（MULTI/EXEC） |
| -------- | ----------------------- | ------------------------ |
| 原子性   | ✅ 是                   | ✅ 是                    |
| 条件判断 | ✅ 支持                 | ❌ 不支持                |
| 循环     | ✅ 支持                 | ❌ 不支持                |
| 错误处理 | ✅ 灵活                 | ⚠️ 有限                  |
| 性能     | ✅ 更好（减少网络往返） | ⚠️ 一般                  |
| 适用场景 | 复杂业务逻辑            | 简单命令组合             |

### 总结

1. **缓存穿透**：查询不存在的数据 → 缓存空值、布隆过滤器
2. **缓存击穿**：热点 key 过期 → 分布式锁、永不过期
3. **缓存雪崩**：大量 key 同时过期 → 随机过期时间、缓存预热
4. **Lua 脚本**：保证多个 Redis 命令的原子性，适用于复杂业务场景

**核心原则**：

-   ✅ 合理设置缓存过期时间（随机化）
-   ✅ 使用分布式锁防止缓存击穿
-   ✅ 缓存空值防止缓存穿透
-   ✅ 使用 Lua 脚本保证复杂操作的原子性
-   ✅ 设计降级方案，保证系统可用性
