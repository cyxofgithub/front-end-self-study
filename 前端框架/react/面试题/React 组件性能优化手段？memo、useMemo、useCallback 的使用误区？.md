# React 组件性能优化手段？memo/useMemo/useCallback 的使用误区？

- 常用优化手段：
    - 组件粒度拆分，状态下放，把状态放到真正使用它的子组件，避免父组件重渲染牵连无关子组件；
    - 用 React.memo 包裹纯展示组件，浅比较 props 决定是否跳过重渲染；
    - 用 useMemo 缓存复杂计算结果，useCallback 缓存函数引用；
    - 路由懒加载、组件动态导入，做代码分割；
    - 长列表用虚拟滚动，只渲染可视区域节点；
    - 避免在 render 里创建新对象 / 新函数，减少 props 引用变化。
- 常见误区：
    - 滥用 memo：浅比较本身有性能开销，对于渲染很快的小组件，包裹 memo 反而得不偿失；
    - 依赖引用失效：传给子组件的对象 / 函数是内联创建的，即使包了 useCallback，依赖数组里的引用变化也会导致缓存失效；
    - 全量缓存：把所有变量都包 useMemo，增加内存占用和初始化开销，只对高开销计算和透传 props 的函数使用。
