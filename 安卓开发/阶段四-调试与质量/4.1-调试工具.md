## 一、Android Studio Debugger

### 断点类型

| 类型 | 说明 | 使用场景 |
|------|------|----------|
| 行断点 | 执行到某行时暂停 | 最常用，检查代码执行流程 |
| 条件断点 | 满足条件时才暂停 | 循环中只关注特定条件 |
| 监视断点 | 字段值变化时暂停 | 追踪变量何时被修改 |
| 异常断点 | 抛出异常时暂停 | 定位崩溃的源头 |

### 设置断点

```
行断点：点击行号左侧（出现红点）
条件断点：右键红点 → Condition → 输入条件表达式
  示例：position == 5     （只在 position 等于 5 时暂停）
  示例：user.name == "张三"（只关注特定用户）

异常断点：Run → View Breakpoints → + → Java Exception Breakpoint
```

### 调试操作

| 操作 | Mac | Windows | 说明 |
|------|-----|---------|------|
| Step Over | F8 | F8 | 执行下一行（不进入方法内部） |
| Step Into | F7 | F7 | 进入方法内部 |
| Step Out | Shift+F8 | Shift+F8 | 跳出当前方法 |
| Resume | Cmd+Option+R | F9 | 继续运行到下一个断点 |
| Evaluate Expression | Option+F8 | Alt+F8 | 执行任意表达式 |

### Evaluate Expression（表达式求值）

调试暂停时，可以执行任意代码：

```kotlin
// 查看变量值
user.name

// 执行方法
user.name.uppercase()

// 创建新对象
SimpleDateFormat("yyyy-MM-dd").format(Date())

// 执行复杂逻辑
items.filter { it.score > 60 }.size
```

> **前端类比**：类似 Chrome DevTools 的 Console 面板，在断点处可以执行任意表达式。

## 二、Logcat 日志

### 日志级别

```kotlin
Log.v("TAG", "Verbose — 最详细的日志")
Log.d("TAG", "Debug — 调试信息")
Log.i("TAG", "Info — 重要信息")
Log.w("TAG", "Warn — 警告")
Log.e("TAG", "Error — 错误")
```

### 过滤技巧

```bash
# 按级别过滤
adb logcat *:E                          # 只看 Error 及以上
adb logcat *:W                          # 只看 Warn 及以上

# 按 TAG 过滤
adb logcat -s MyTag:V                   # 只看 MyTag 的日志
adb logcat -s MyTag:D AnotherTag:I      # 多个 TAG

# 按关键字过滤
adb logcat | grep "keyword"
adb logcat | grep -i "keyword"          # 忽略大小写

# 按包名过滤
adb logcat --pid=$(adb shell pidof com.example.app)

# 组合过滤
adb logcat -s MyTag:D *:E              # MyTag 的 Debug + 所有 Error
```

### Android Studio 中过滤

```
Logcat 面板顶部：
- 下拉选择设备
- 下拉选择应用包名
- 搜索框输入：tag:MyTag level:ERROR
- 正则过滤：~ "pattern"
```

### 日志规范

```kotlin
// 好的做法
private const val TAG = "UserViewModel"
Log.d(TAG, "loadUser: userId=$userId")
Log.e(TAG, "loadUser failed", exception)  // 附带异常堆栈

// 不好的做法
Log.d("xxx", "here")     // TAG 不明确
Log.d(TAG, user.toString())  // 大对象不要打印
```

## 三、Layout Inspector

### 用途

查看运行时的 View 树结构，检查布局问题。

### 使用方法

```
Android Studio → Tools → Layout Inspector → 选择进程
```

### 功能

| 功能 | 说明 |
|------|------|
| View 树 | 查看完整的 View 层级 |
| 属性面板 | 查看和修改 View 属性 |
| 3D 模式 | 查看布局的立体层级 |
| 渲染性能 | 查看 View 的绘制耗时 |

> **前端类比**：Layout Inspector ≈ Chrome DevTools 的 Elements 面板 + Layers 面板。

### 常见检查

1. **布局层级过深** → 需要优化，减少嵌套
2. **View 大小不对** → 检查 match_parent / wrap_content 设置
3. **View 不可见** → 检查 visibility、alpha、被其他 View 遮挡
4. **间距不对** → 检查 margin / padding

## 四、CodeLocator

CodeLocator 是内部工具，用于快速定位视图组件对应的代码。

### 核心功能

```
手机上点击某个元素
    → 自动定位到：
        - 对应的 XML 布局文件
        - 对应的 Activity / Fragment
        - 对应的 View ID
```

### 使用场景

1. **看别人的代码**：点击屏幕上的元素，直接跳到代码位置
2. **定位 Bug**：看到显示不对的地方，点击定位到代码
3. **了解项目结构**：快速了解某个页面用了哪些组件

> **前端类比**：CodeLocator ≈ Chrome DevTools 的 "Inspect Element" + 点击跳转到源码。

## 五、APK 反编译

### 工具

| 工具 | 用途 |
|------|------|
| `apktool` | 反编译资源和 smali 代码 |
| `jadx` | 反编译为 Java 源码 |
| `Android Studio` | 直接分析 APK（Build → Analyze APK） |

### jadx 使用

```bash
# 命令行
jadx -d output/ app.apk

# GUI 版本
jadx-gui app.apk
```

### 使用场景

1. 查看第三方库的实现逻辑
2. 分析竞品的实现方式
3. 排查线上包的问题

## 六、实用调试技巧

### 1. 快速定位崩溃

```bash
# 获取最近的崩溃日志
adb logcat -b crash -d
```

### 2. 模拟网络延迟

```bash
# 设置网络延迟（需要 root 或模拟器）
adb shell settings put global captive_portal_mode 1

# Charles/Proxyman 抓包
# 设置手机代理到电脑 IP，用抓包工具分析网络请求
```

### 3. 查看数据库

```bash
# 导出应用数据库
adb shell run-as com.example.app
cd databases/
cat data.db > /sdcard/data.db
adb pull /sdcard/data.db
# 用 DB Browser for SQLite 查看
```

### 4. 查看 SharedPreferences

```bash
adb shell run-as com.example.app
cd shared_prefs/
cat *.xml
```
