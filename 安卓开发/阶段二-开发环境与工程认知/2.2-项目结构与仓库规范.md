## 二、各子模块职责

### lib_base — 基础能力层

```
lib_base/
├── network/        网络请求封装（FANet）
├── storage/        本地存储（SharedPreferences, Room）
├── utils/          工具类（日期、格式化、加密等）
├── extensios/      Kotlin 扩展函数
└── base/           基类（BaseActivity, BaseFragment, BaseViewModel）
```

**职责**：提供所有模块共用的基础能力，不包含业务逻辑。

### lib_common — 公共 UI 组件

```
lib_common/
├── widgets/        自定义 View（加载状态、空状态、轮播等）
├── adapter/        RecyclerView Adapter 基类
├── dialog/         通用弹窗
└── layout/         公共布局
```

**职责**：提供可复用的 UI 组件，不依赖具体业务模块。

### module_xxx — 业务模块

```
module_home/
├── api/            该模块的接口定义
├── model/          数据模型（data class）
├── repository/     数据仓库
├── viewmodel/      ViewModel
├── ui/             页面（Activity + Fragment）
└── di/             依赖注入配置
```

**职责**：独立的功能模块，模块之间通过路由通信，不直接依赖。

### lib_protocol — 接口协议

```
lib_protocol/
├── bean/           数据类定义
├── api/            接口描述
└── constant/       常量定义
```

**职责**：定义前后端接口协议，独立模块可以降低耦合。

## 三、AndroidManifest.xml 详解

### 什么是 AndroidManifest？

`AndroidManifest.xml` 是 Android 项目的**核心配置文件**，位于每个模块的 `src/main/` 目录下。它向 Android 系统声明了应用的所有组件、权限、入口点等关键信息。没有在 Manifest 中声明的 Activity / Service 等组件无法被系统识别。

> **前端类比**：AndroidManifest ≈ `package.json` + `vite.config.ts` + `index.html` 的合体。它既声明了应用包含哪些"页面"（Activity），又声明了需要哪些系统权限，还定义了应用的入口。

### 前端类比对照

```
AndroidManifest.xml              前端类比
───────────────────              ──────────
<application>               ≈   应用根配置（类似 Vue/React App 根组件）
<activity>                  ≈   路由页面注册（router.addRoute）
<intent-filter>             ≈   路由规则（path + 匹配条件）
<uses-permission>           ≈   浏览器权限申请（Notification.requestPermission）
<meta-data>                 ≈   环境变量 / 插件配置（.env + plugin config）
<service>                   ≈   Web Worker / 后台任务
<receiver>                  ≈   全局事件监听（addEventListener on window）
```

### Manifest 基本结构

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.kugou.fanxing">          <!-- 应用包名，唯一标识 -->

    <!-- 权限声明 -->
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.CAMERA" />

    <application
        android:name=".App"                         <!-- Application 类 -->
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"          <!-- 应用图标 -->
        android:label="@string/app_name"            <!-- 应用名称 -->
        android:theme="@style/AppTheme"             <!-- 全局主题 -->
        android:networkSecurityConfig="@xml/network_security_config">

        <!-- Activity 声明 -->
        <activity
            android:name=".ui.MainActivity"
            android:exported="true">                <!-- 可被外部调用 -->
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <activity
            android:name=".ui.player.PlayerActivity"
            android:screenOrientation="portrait"    <!-- 竖屏锁定 -->
            android:configChanges="orientation|screenSize" />

        <!-- Service 声明 -->
        <service
            android:name=".player.PlaybackService"
            android:exported="false" />

        <!-- Receiver 声明 -->
        <receiver
            android:name=".receiver.NetworkReceiver"
            android:exported="true">
            <intent-filter>
                <action android:name="android.net.conn.CONNECTIVITY_CHANGE" />
            </intent-filter>
        </receiver>

        <!-- meta-data 配置 -->
        <meta-data
            android:name="com.kugou.CHANNEL"
            android:value="google_play" />
    </application>
</manifest>
```

### 核心元素说明

#### `<manifest>` 根标签

| 属性 | 说明 |
|------|------|
| `package` | 应用包名，全局唯一标识符（如 `com.kugou.fanxing`） |
| `android:versionCode` | 版本号（整数），用于判断升级 |
| `android:versionName` | 版本名（字符串），展示给用户（如 `"2.1.0"`） |

> **前端类比**：`package` ≈ `package.json` 的 `name`，`versionCode/versionName` ≈ `version`。

#### `<application>` 应用配置

| 属性 | 说明 |
|------|------|
| `android:name` | 自定义 Application 类（应用入口，类似前端 App 根组件） |
| `android:icon` | 应用图标 |
| `android:label` | 应用名称 |
| `android:theme` | 全局主题样式 |
| `android:networkSecurityConfig` | 网络安全配置（Android 9+ 默认不允许 HTTP） |
| `android:largeHeap` | 请求更大的堆内存 |

#### `<activity>` 页面声明

每个 Activity **必须**在 Manifest 中声明才能使用：

```xml
<activity
    android:name=".ui.DetailActivity"            <!-- Activity 类名 -->
    android:exported="false"                     <!-- 是否允许外部应用调用 -->
    android:screenOrientation="portrait"         <!-- 屏幕方向 -->
    android:windowSoftInputMode="adjustResize"   <!-- 键盘弹出时的行为 -->
    android:launchMode="singleTop"               <!-- 启动模式 -->
    android:configChanges="orientation|screenSize" />  <!-- 自行处理配置变更 -->
```

**`android:exported` 说明**：
- `true`：该 Activity 可以被其他应用或系统调用（如桌面启动器、其他应用跳转）
- `false`：只能在应用内部使用
- **启动页 Activity 必须设为 `true`**，否则桌面图标无法打开应用

**`android:launchMode` 启动模式**：

| 模式 | 行为 | 前端类比 |
|------|------|----------|
| `standard`（默认） | 每次跳转创建新实例 | `router.push()`（每次 push 新页面） |
| `singleTop` | 栈顶复用，否则新建 | 类似 `router.replace()` + 去重 |
| `singleTask` | 栈内只有一个实例，清除其上所有 Activity | 类似跳回首页并清空历史栈 |
| `singleInstance` | 独立任务栈，全局单例 | 类似独立窗口/iframe |

#### `<intent-filter>` 意图过滤器

声明该组件能响应哪些 Intent，相当于路由规则：

```xml
<!-- 启动页：告诉系统这是入口 Activity -->
<intent-filter>
    <action android:name="android.intent.action.MAIN" />
    <category android:name="android.intent.category.LAUNCHER" />
</intent-filter>

<!-- 深链接：通过 URL 打开特定页面 -->
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="fanxing" android:host="player" />
    <!-- 匹配：fanxing://player?id=123 -->
</intent-filter>
```

> **前端类比**：
> - `MAIN + LAUNCHER` ≈ `index.html` 入口页面
> - 深链接 `fanxing://player` ≈ 前端路由 `/player`，可以通过 URL Scheme 从外部（浏览器、其他应用）直接打开应用内的特定页面

#### `<uses-permission>` 权限声明

应用需要的系统权限必须在此声明，敏感权限还需运行时动态申请：

```xml
<!-- 常见权限 -->
<uses-permission android:name="android.permission.INTERNET" />              <!-- 网络 -->
<uses-permission android:name="android.permission.CAMERA" />               <!-- 相机 -->
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" /><!-- 读存储 -->
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE" /><!-- 写存储 -->
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" /> <!-- 精确定位 -->
<uses-permission android:name="android.permission.RECORD_AUDIO" />         <!-- 录音 -->
```

| 权限类型 | 说明 | 是否需要运行时申请 |
|----------|------|-------------------|
| 普通权限 | 如 `INTERNET`、`VIBRATE`、`WAKE_LOCK` | 不需要，安装时自动授予 |
| 危险权限 | 如 `CAMERA`、`LOCATION`、`READ_CONTACTS` | **需要**，必须代码中动态申请 |

> **前端类比**：普通权限 ≈ `<link rel="manifest">` 中的声明；危险权限 ≈ `Notification.requestPermission()`、`navigator.geolocation.getCurrentPosition()`，需要用户弹窗确认。

#### `<meta-data>` 元数据

键值对形式的配置信息，常用于第三方 SDK 初始化：

```xml
<meta-data
    android:name="com.kugou.CHANNEL"
    android:value="google_play" />

<!-- 在代码中读取 -->
val metaData = packageManager.getApplicationInfo(packageName, PackageManager.GET_META_DATA).metaData
val channel = metaData.getString("com.kugou.CHANNEL")  // "google_play"
```

> **前端类比**：类似 `.env` 环境变量（`VUE_APP_CHANNEL=google_play`），在构建时注入或运行时读取。

### 多模块中的 Manifest 合并

在多模块项目中，每个模块有自己的 `AndroidManifest.xml`，最终构建时会**合并**为一个：

```
app_fanxingv2/src/main/AndroidManifest.xml        ← 主壳 Manifest
  + module_home/src/main/AndroidManifest.xml       ← 首页模块
  + module_player/src/main/AndroidManifest.xml     ← 播放器模块
  + lib_common/src/main/AndroidManifest.xml        ← 公共库
  ─────────────────────────────────────
  = 最终合并的 AndroidManifest.xml（打包进 APK）
```

**合并规则**：
- 所有模块的 `<activity>`、`<service>` 等组件都会合并
- 同名属性以后声明的为准（可通过 `tools:replace` 控制）
- 权限声明会去重合并

**常见冲突处理**：

```xml
<!-- 使用 tools 命名空间控制合并行为 -->
<manifest xmlns:tools="http://schemas.android.com/tools">

    <!-- 强制替换库模块中的属性值 -->
    <activity
        android:name=".ui.MainActivity"
        android:theme="@style/CustomTheme"
        tools:replace="android:theme" />

    <!-- 移除库模块中的某个权限 -->
    <uses-permission
        android:name="android.permission.READ_PHONE_STATE"
        tools:node="remove" />
</manifest>
```

### 常见面试题 / 实战要点

1. **新建 Activity 忘记注册**：运行时抛出 `ActivityNotFoundException`，需在 Manifest 中添加 `<activity>` 声明
2. **网络请求失败（Android 9+）**：默认禁止 HTTP 明文请求，需在 `networkSecurityConfig` 中配置允许的域名或使用 HTTPS
3. **`exported` 必须显式声明**：Android 12+ 要求所有带有 `<intent-filter>` 的组件必须显式设置 `android:exported`
4. **深链接接入**：通过 `<intent-filter>` + `<data>` 实现从浏览器或外部应用直接打开应用内页面

## 四、模块间通信

### 路由导航

模块之间不能直接引用 Activity 类，需要通过路由：

```kotlin
// 不好的做法（模块间直接依赖）
val intent = Intent(this, PlayerActivity::class.java)  // 可能不在当前模块

// 好的做法（通过路由）
Router.navigate("/player/detail", mapOf("songId" to "123"))
```

> **前端类比**：模块路由 ≈ 微前端的跨应用通信，各模块独立部署，通过约定好的路由协议通信。

### 事件总线

```kotlin
// 发送事件
EventBus.post(LoginSuccessEvent(userId))

// 接收事件
@Subscribe(threadMode = ThreadMode.MAIN)
fun onLoginSuccess(event: LoginSuccessEvent) {
    updateUI()
}
```

## 五、开发规范

### 代码风格

- 文件命名：`PascalCase`（如 `UserViewModel.kt`）
- 变量命名：`camelCase`（如 `userName`）
- 常量：`UPPER_SNAKE_CASE`（如 `MAX_RETRY_COUNT`）
- 布局文件：`snake_case`（如 `activity_main.xml`, `item_user.xml`）
- 资源 ID：`snake_case`（如 `@+id/user_name_text`）

### 包结构

```
com.kugou.fanxing.module.home/
├── api/                接口
├── model/              数据模型
├── repository/         数据层
├── viewmodel/          ViewModel
├── ui/                 UI 层
│   ├── HomeActivity.kt
│   ├── HomeFragment.kt
│   └── adapter/        列表适配器
└── di/                 依赖注入
```

### Git 规范

```
feat: 新增用户个人主页功能
fix: 修复播放器在后台恢复时的崩溃问题
refactor: 重构首页列表加载逻辑
docs: 更新接口文档
chore: 升级 Gradle 到 8.0
```

### Code Review 要点

1. 功能是否正确实现
2. 是否有内存泄漏风险
3. 是否遵循项目架构规范
4. 异常处理是否完善
5. 命名是否清晰

## 本章知识点总结

|--------|------|
| 仓库结构 | 主壳工程 + 公共基础库 + 业务模块 + 路由 + 构建逻辑 |

| 模块间通信 | 通过路由导航，不直接引用其他模块的 Activity |
| 代码风格 | PascalCase 文件名、camelCase 变量、snake_case 布局/资源 |
| Git 规范 | `feat:`/`fix:`/`refactor:`/`docs:`/`chore:` 提交前缀 |
