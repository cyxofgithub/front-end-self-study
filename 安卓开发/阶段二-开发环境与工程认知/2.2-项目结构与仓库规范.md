# 2.2 项目结构与仓库规范

> 理解团队项目的仓库结构、模块划分和开发规范。

---

## 一、仓库结构

### 航母主仓库 / 繁星主仓库

团队使用多仓库 + 多模块的架构：

```
fanxing_android_v2/           繁星 Android V2 主工程
├── app_fanxingv2/            主壳工程（Application 入口）
│   ├── src/main/
│   │   ├── java/
│   │   ├── res/
│   │   └── AndroidManifest.xml
│   └── build.gradle
│
├── fanxing_lib/              公共基础库
│   ├── lib_base/             基础能力（网络、存储、工具）
│   ├── lib_common/           公共 UI 组件
│   └── lib_protocol/         接口协议定义
│
├── fanxing_module/           业务模块
│   ├── module_home/          首页
│   ├── module_live/          直播
│   ├── module_user/          用户
│   ├── module_player/        播放器
│   └── module_im/            即时通讯
│
├── fanxing_alline/           模块化路由
│
├── build-logic/              构建逻辑
│   └── convention-plugins/   Convention Plugins
│
├── build.gradle              项目级构建配置
├── settings.gradle           模块声明
└── gradle.properties         全局属性
```

### 前端类比

```
Android 项目结构                前端 Monorepo
─────────────────               ──────────
app/                        ≈   apps/mobile/
lib_base/                   ≈   packages/core/
lib_common/                 ≈   packages/ui-components/
module_home/                ≈   packages/home/
settings.gradle             ≈   pnpm-workspace.yaml
build.gradle                ≈   package.json（根目录）
gradle.properties           ≈   tsconfig.json
build-logic/                ≈   tools/build-config/
```

## 二、各子模块职责

### lib_base — 基础能力层

```
lib_base/
├── network/        网络请求封装（FANet）
├── storage/        本地存储（SharedPreferences, Room）
├── utils/          工具类（日期、格式化、加密等）
├── extensios/      Kotlin 扩展函数
└── base/           基类（BaseActivity, BaseFragment, BaseViewModel）
```

**职责**：提供所有模块共用的基础能力，不包含业务逻辑。

### lib_common — 公共 UI 组件

```
lib_common/
├── widgets/        自定义 View（加载状态、空状态、轮播等）
├── adapter/        RecyclerView Adapter 基类
├── dialog/         通用弹窗
└── layout/         公共布局
```

**职责**：提供可复用的 UI 组件，不依赖具体业务模块。

### module_xxx — 业务模块

```
module_home/
├── api/            该模块的接口定义
├── model/          数据模型（data class）
├── repository/     数据仓库
├── viewmodel/      ViewModel
├── ui/             页面（Activity + Fragment）
└── di/             依赖注入配置
```

**职责**：独立的功能模块，模块之间通过路由通信，不直接依赖。

### lib_protocol — 接口协议

```
lib_protocol/
├── bean/           数据类定义
├── api/            接口描述
└── constant/       常量定义
```

**职责**：定义前后端接口协议，独立模块可以降低耦合。

## 三、模块间通信

### 路由导航

模块之间不能直接引用 Activity 类，需要通过路由：

```kotlin
// 不好的做法（模块间直接依赖）
val intent = Intent(this, PlayerActivity::class.java)  // 可能不在当前模块

// 好的做法（通过路由）
Router.navigate("/player/detail", mapOf("songId" to "123"))
```

> **前端类比**：模块路由 ≈ 微前端的跨应用通信，各模块独立部署，通过约定好的路由协议通信。

### 事件总线

```kotlin
// 发送事件
EventBus.post(LoginSuccessEvent(userId))

// 接收事件
@Subscribe(threadMode = ThreadMode.MAIN)
fun onLoginSuccess(event: LoginSuccessEvent) {
    updateUI()
}
```

## 四、开发规范

### 代码风格

- 文件命名：`PascalCase`（如 `UserViewModel.kt`）
- 变量命名：`camelCase`（如 `userName`）
- 常量：`UPPER_SNAKE_CASE`（如 `MAX_RETRY_COUNT`）
- 布局文件：`snake_case`（如 `activity_main.xml`, `item_user.xml`）
- 资源 ID：`snake_case`（如 `@+id/user_name_text`）

### 包结构

```
com.kugou.fanxing.module.home/
├── api/                接口
├── model/              数据模型
├── repository/         数据层
├── viewmodel/          ViewModel
├── ui/                 UI 层
│   ├── HomeActivity.kt
│   ├── HomeFragment.kt
│   └── adapter/        列表适配器
└── di/                 依赖注入
```

### Git 规范

```
feat: 新增用户个人主页功能
fix: 修复播放器在后台恢复时的崩溃问题
refactor: 重构首页列表加载逻辑
docs: 更新接口文档
chore: 升级 Gradle 到 8.0
```

### Code Review 要点

1. 功能是否正确实现
2. 是否有内存泄漏风险
3. 是否遵循项目架构规范
4. 异常处理是否完善
5. 命名是否清晰

## 参考答案

### 第 1 题

```bash
# 克隆仓库
git clone <仓库地址>
cd fanxing_android_v2

# 用 Android Studio 打开
# File → Open → 选择项目根目录
# 等待 Gradle 同步完成（首次可能需要较长时间）

# 如果同步失败，检查：
# 1. JDK 版本是否正确（推荐 JDK 17）
# 2. Gradle 版本是否匹配
# 3. 网络代理配置（gradle.properties 中的代理设置）
```

### 第 2 题

```groovy
// settings.gradle 示例
include ':app_fanxingv2'
include ':fanxing_lib:lib_base'
include ':fanxing_lib:lib_common'
include ':fanxing_lib:lib_protocol'
include ':fanxing_module:module_home'
include ':fanxing_module:module_live'
include ':fanxing_module:module_user'
include ':fanxing_module:module_player'
include ':fanxing_alline'
```

每个 `include` 行声明一个模块，对应一个独立的 `build.gradle`。

### 第 3 题

**步骤：**

1. 在 Android Studio 中展开 `fanxing_lib/lib_base/` 目录
2. 找到 `network/` 包，查看 FANet 相关类
3. 重点关注：
   - 请求构建器（`FANet.get()`/`FANet.post()`）
   - 回调接口（`Callback<T>`）
   - 响应包装类（`BaseResponse<T>`）
   - 拦截器（统一添加 header、token 等）

### 第 4 题

**操作步骤：** 访问 Wiki，重点阅读项目架构图和模块依赖关系图。

## 本章知识点总结

| 知识点 | 要点 |
|--------|------|
| 仓库结构 | 主壳工程 + 公共基础库 + 业务模块 + 路由 + 构建逻辑 |
| lib_base | 网络请求、存储、工具类、基类；不包含业务逻辑 |
| lib_common | 公共 UI 组件、Adapter 基类、通用弹窗；不依赖业务模块 |
| module_xxx | 独立业务模块；api/model/repository/viewmodel/ui/di 分层 |
| 模块间通信 | 通过路由导航，不直接引用其他模块的 Activity |
| 代码风格 | PascalCase 文件名、camelCase 变量、snake_case 布局/资源 |
| Git 规范 | `feat:`/`fix:`/`refactor:`/`docs:`/`chore:` 提交前缀 |
