# 1.4 Java 异常处理

> 掌握 try-catch-finally 和 Java 异常体系，学会正确处理程序中的错误。

---

## 一、异常体系

```
Throwable（所有错误的祖先）
├── Error（系统级错误，不应捕获）
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── ...
└── Exception（可处理的异常）
    ├── 受检异常（Checked Exception）
    │   ├── IOException
    │   ├── SQLException
    │   ├── FileNotFoundException
    │   └── ...（必须处理：try-catch 或 throws）
    └── 非受检异常（Unchecked / RuntimeException）
        ├── NullPointerException
        ├── ArrayIndexOutOfBoundsException
        ├── ClassCastException
        ├── IllegalArgumentException
        └── ...（可选处理）
```

### 前端类比

| Java | JavaScript | 说明 |
|------|-----------|------|
| `Exception` | `Error` | 可捕获的异常 |
| `RuntimeException` | `TypeError`, `ReferenceError` | 编程错误 |
| `IOException` | `NetworkError` | 外部原因导致的错误 |
| `Error`（Java） | — | 系统崩溃级错误，JS 中没有对应 |

## 二、try-catch-finally

### 基本用法

```java
try {
    // 可能出错的代码
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // 处理特定异常
    System.out.println("计算错误: " + e.getMessage());
} catch (Exception e) {
    // 处理其他异常
    System.out.println("未知错误: " + e.getMessage());
} finally {
    // 无论是否异常，都会执行
    System.out.println("清理资源");
}
```

### 多异常捕获（Java 7+）

```java
try {
    // ...
} catch (IOException | SQLException e) {
    // 用 | 合并多个异常类型
    System.out.println("操作失败: " + e.getMessage());
}
```

### try-with-resources（Java 7+）

自动关闭实现了 `AutoCloseable` 的资源：

```java
// 旧写法 — 手动关闭
BufferedReader reader = null;
try {
    reader = new BufferedReader(new FileReader("data.txt"));
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (reader != null) {
        try {
            reader.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

// 新写法 — 自动关闭（推荐）
try (BufferedReader reader = new BufferedReader(new FileReader("data.txt"))) {
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// reader 在 try 块结束后自动关闭，无需 finally
```

## 三、throw 与 throws

### throw — 抛出异常

```java
public void setAge(int age) {
    if (age < 0 || age > 150) {
        throw new IllegalArgumentException("年龄不合法: " + age);
    }
    this.age = age;
}
```

### throws — 声明异常

```java
// 声明方法可能抛出的受检异常
public String readFile(String path) throws IOException, FileNotFoundException {
    BufferedReader reader = new BufferedReader(new FileReader(path));
    return reader.readLine();
}

// 调用方必须处理
try {
    String content = readFile("data.txt");
} catch (IOException e) {
    System.out.println("读取失败: " + e.getMessage());
}
```

> **受检异常 vs 非受检异常**：
> - 受检异常（`IOException` 等）：编译器强制要求处理
> - 非受检异常（`NullPointerException` 等）：编译器不强制，但运行时会崩溃

## 四、自定义异常

```java
// 自定义受检异常
public class BusinessException extends Exception {
    private int code;

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    public int getCode() {
        return code;
    }
}

// 自定义非受检异常
public class ValidationException extends RuntimeException {
    public ValidationException(String message) {
        super(message);
    }
}

// 使用
public void withdraw(double amount) throws BusinessException {
    if (amount < 0) {
        throw new ValidationException("金额不能为负数");  // 非受检，不需要 throws
    }
    if (amount > balance) {
        throw new BusinessException(1001, "余额不足");   // 受检，需要 throws
    }
    balance -= amount;
}
```

## 五、异常链

在捕获一个异常后，包装成另一个异常抛出：

```java
try {
    String data = readFromNetwork();
} catch (IOException e) {
    // 保留原始异常信息（cause）
    throw new BusinessException(5001, "数据加载失败", e);
}

// 自定义异常支持 cause
public class BusinessException extends Exception {
    public BusinessException(int code, String message, Throwable cause) {
        super(message, cause);  // 传入原始异常
    }
}
```

## 六、常见异常速查

| 异常 | 触发场景 | 修复方式 |
|------|----------|----------|
| `NullPointerException` | 调用 null 对象的方法 | 空值检查，使用 Kotlin 空安全 |
| `ClassCastException` | 错误的类型转换 | `instanceof` 先检查 |
| `ArrayIndexOutOfBoundsException` | 数组越界 | 检查 length |
| `NumberFormatException` | `"abc"` 转数字 | try-catch 包裹 |
| `IllegalArgumentException` | 参数不合法 | 校验参数 |
| `IllegalStateException` | 对象状态不对 | 检查调用时机 |
| `ConcurrentModificationException` | 遍历时修改集合 | 用 Iterator.remove() |
| `IOException` | 文件/网络操作失败 | try-catch 处理 |

---

## 七、最佳实践

1. **只捕获你能处理的异常**——不要空 catch 吞掉错误
2. **优先使用非受检异常**——受检异常强制调用方处理，容易导致代码啰嗦
3. **finally 中不要 return**——会覆盖 try 中的返回值
4. **用 try-with-resources**——替代手动 finally 关闭资源
5. **保留异常链**——`new XxxException("msg", cause)` 不要丢失原始信息
