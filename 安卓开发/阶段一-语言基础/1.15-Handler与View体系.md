# 1.15 Handler 与 View 体系

> 理解 Android 的线程通信机制和 View 绘制流程。

---

## 一、Handler 机制

### 为什么需要 Handler？

Android 的 UI 操作**只能在主线程（UI 线程）执行**。子线程做完耗时操作后，需要通知主线程更新 UI，这就是 Handler 的作用。

```
┌──────────────┐         ┌──────────────────┐
│   子线程      │         │     主线程         │
│              │         │                  │
│  耗时操作     │         │  Looper.loop()   │
│  (网络请求)   │         │    ↓             │
│      │       │         │  MessageQueue    │
│      │       │         │    ↓             │
│      └───────┼──消息──→│  Handler         │
│              │         │    ↓             │
│              │         │  handleMessage() │
│              │         │    ↓             │
│              │         │  更新 UI          │
└──────────────┘         └──────────────────┘
```

### 四大核心组件

| 组件 | 作用 |
|------|------|
| **Message** | 携带数据的消息对象 |
| **MessageQueue** | 消息队列，按时间排序 |
| **Handler** | 发送和处理消息 |
| **Looper** | 不断从 MessageQueue 取出消息并分发给 Handler |

### 前端类比

```
Handler 机制                    JavaScript
──────────────                  ──────────
主线程 + Looper             ≈   单线程事件循环（Event Loop）
MessageQueue                ≈   任务队列（Task Queue）
Handler.sendMessage()       ≈   setTimeout() / Promise.resolve()
子线程 → 主线程             ≈   Web Worker → 主线程 postMessage()
```

### 基本用法

```kotlin
// 方式 1：发送 Message 对象
class MyActivity : Activity() {
    private val handler = object : Handler(Looper.getMainLooper()) {
        override fun handleMessage(msg: Message) {
            when (msg.what) {
                1 -> textView.text = "收到消息: ${msg.obj}"
            }
        }
    }

    fun doWork() {
        Thread {
            // 子线程执行耗时操作
            val data = fetchFromNetwork()
            // 发送消息到主线程
            val message = handler.obtainMessage(1, data)
            handler.sendMessage(message)
        }.start()
    }
}

// 方式 2：发送 Runnable（更简洁）
fun doWork() {
    Thread {
        val data = fetchFromNetwork()
        handler.post {
            // 这段代码在主线程执行
            textView.text = data
        }
    }.start()
}

// 方式 3：延迟执行
handler.postDelayed({
    println("3 秒后执行")
}, 3000)
```

### Kotlin 协程（推荐替代方案）

现代 Android 开发推荐用协程替代 Handler：

```kotlin
// 用协程做同样的事（更简洁）
viewModelScope.launch {
    val data = withContext(Dispatchers.IO) {
        fetchFromNetwork()  // 自动在 IO 线程执行
    }
    textView.text = data    // 自动回到主线程
}
```

## 二、View 绘制流程

每个 View 在屏幕上显示需要经历三个步骤：

```
onMeasure()  →  onLayout()  →  onDraw()
  测量大小       确定位置       绘制内容
```

### onMeasure — 测量大小

```kotlin
override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
    // MeasureSpec 包含：模式 + 尺寸
    // EXACTLY   — 精确值（如 layout_width="200dp" 或 match_parent）
    // AT_MOST   — 最大值（如 wrap_content，不能超过父容器）
    // UNSPECIFIED — 无限制（很少用）

    val widthMode = MeasureSpec.getMode(widthMeasureSpec)
    val widthSize = MeasureSpec.getSize(widthMeasureSpec)

    // 计算自己需要的大小
    super.onMeasure(widthMeasureSpec, heightMeasureSpec)
}
```

### onLayout — 确定子 View 位置

```kotlin
override fun onLayout(changed: Boolean, left: Int, top: Int, right: Int, bottom: Int) {
    // 确定每个子 View 的位置
    // 只有 ViewGroup 需要实现
    val childCount = childCount
    for (i in 0 until childCount) {
        val child = getChildAt(i)
        child.layout(left, top, left + child.measuredWidth, top + child.measuredHeight)
    }
}
```

### onDraw — 绘制内容

```kotlin
override fun onDraw(canvas: Canvas) {
    super.onDraw(canvas)

    // 用 Paint 定义画笔样式
    val paint = Paint().apply {
        color = Color.RED
        textSize = 50f
        isAntiAlias = true  // 抗锯齿
    }

    // 在 Canvas 上绘制
    canvas.drawText("Hello", 100f, 100f, paint)
    canvas.drawCircle(200f, 200f, 50f, paint)
    canvas.drawRect(50f, 300f, 300f, 500f, paint)
}
```

### 前端类比

```
Android View 绘制              浏览器渲染流程
─────────────────              ──────────────
onMeasure()               ≈   Layout（计算大小）
onLayout()                ≈   Layout（确定位置）
onDraw()                  ≈   Paint + Composite
requestLayout()           ≈   触发 reflow
invalidate()              ≈   触发 repaint
```

### requestLayout vs invalidate

```kotlin
// requestLayout — 大小/位置变了，触发完整流程（measure → layout → draw）
view.requestLayout()

// invalidate — 只是外观变了，只需重新 draw
view.invalidate()
```

> **性能原则**：只改外观用 `invalidate()`，只有大小/位置变化才用 `requestLayout()`。

## 三、触摸事件处理

### 事件分发机制

```
Activity.dispatchTouchEvent()
        │
        ▼
ViewGroup.dispatchTouchEvent()
        │
        ▼
ViewGroup.onInterceptTouchEvent()  → 是否拦截？
        │                    │
    不拦截                  拦截
        │                    │
        ▼                    ▼
子 View.onTouchEvent()    ViewGroup.onTouchEvent()
```

### 三大方法

| 方法 | 说明 | 返回值含义 |
|------|------|-----------|
| `dispatchTouchEvent()` | 分发事件 | `true` = 消费了，不再往下传 |
| `onInterceptTouchEvent()` | 拦截事件（ViewGroup 独有） | `true` = 拦截，自己处理 |
| `onTouchEvent()` | 处理触摸事件 | `true` = 消费了，不再往上冒泡 |

### 前端类比

```
Android 事件分发               DOM 事件模型
─────────────────              ──────────
dispatchTouchEvent()       ≈   addEventListener 的捕获阶段
onInterceptTouchEvent()    ≈   stopPropagation()（拦截）
onTouchEvent()             ≈   事件冒泡阶段的 handler
返回 true                  ≈   stopPropagation()（停止传播）
```

### 处理点击事件

```kotlin
// 方式 1：setOnClickListener（最常用）
button.setOnClickListener {
    println("按钮被点击")
}

// 方式 2：setOnTouchListener（更细粒度控制）
view.setOnTouchListener { v, event ->
    when (event.action) {
        MotionEvent.ACTION_DOWN -> {
            println("手指按下")
            true
        }
        MotionEvent.ACTION_MOVE -> {
            println("手指移动: (${event.x}, ${event.y})")
            true
        }
        MotionEvent.ACTION_UP -> {
            println("手指抬起")
            true
        }
    }
    true  // 返回 true 表示消费了事件
}
```

### 自定义 View 中的触摸事件

```kotlin
class DraggableView(context: Context) : View(context) {
    private var lastX = 0f
    private var lastY = 0f

    override fun onTouchEvent(event: MotionEvent): Boolean {
        when (event.action) {
            MotionEvent.ACTION_DOWN -> {
                lastX = event.x
                lastY = event.y
                return true  // 必须返回 true 才能收到后续事件
            }
            MotionEvent.ACTION_MOVE -> {
                val dx = event.x - lastX
                val dy = event.y - lastY
                // 移动 View
                translationX += dx
                translationY += dy
                lastX = event.x
                lastY = event.y
            }
        }
        return super.onTouchEvent(event)
    }
}
```

## 参考答案

### 第 1 题

```kotlin
class CountdownActivity : AppCompatActivity() {
    private val handler = Handler(Looper.getMainLooper())
    private var remainingSeconds = 60

    private val countdownRunnable = object : Runnable {
        override fun run() {
            if (remainingSeconds > 0) {
                tvCountdown.text = "剩余 ${remainingSeconds} 秒"
                remainingSeconds--
                handler.postDelayed(this, 1000)
            } else {
                tvCountdown.text = "倒计时结束！"
            }
        }
    }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_countdown)
        handler.post(countdownRunnable)
    }

    override fun onDestroy() {
        super.onDestroy()
        handler.removeCallbacks(countdownRunnable)  // 防止内存泄漏
    }
}
```

}

### 第 3 题

```kotlin
class DraggableView(context: Context, attrs: AttributeSet) : View(context, attrs) {
    private var lastX = 0f
    private var lastY = 0f

    override fun onTouchEvent(event: MotionEvent): Boolean {
        when (event.action) {
            MotionEvent.ACTION_DOWN -> {
                lastX = event.rawX
                lastY = event.rawY
                return true
            }
            MotionEvent.ACTION_MOVE -> {
                val dx = event.rawX - lastX
                val dy = event.rawY - lastY
                translationX += dx
                translationY += dy
                lastX = event.rawX
                lastY = event.rawY

            MotionEvent.ACTION_UP -> {
                println("拖拽结束，位置: ($translationX, $translationY)")
            }
        }
        return super.onTouchEvent(event)
    }
}
```

### 第 4 题

```kotlin
class CountdownCoroutineActivity : AppCompatActivity() {
    private var remainingSeconds = 60

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_countdown)

        lifecycleScope.launch {
            while (remainingSeconds > 0) {
                tvCountdown.text = "剩余 ${remainingSeconds} 秒"
                remainingSeconds--
                delay(1000)  // 挂起 1 秒，不阻塞线程
            }
            tvCountdown.text = "倒计时结束！"
        }
    }
}
```

## 本章知识点总结

| 知识点 | 要点 |
|--------|------|
| Handler 机制 | 子线程通过 Handler 向主线程发消息更新 UI；四大组件：Message/MessageQueue/Handler/Looper |
| Handler 用法 | `sendMessage` + `handleMessage`；`post(Runnable)`；`postDelayed` 延迟执行 |
| View 绘制流程 | `onMeasure`（测量大小）→ `onLayout`（确定位置）→ `onDraw`（绘制内容） |
| requestLayout vs invalidate | 大小/位置变化用 `requestLayout`；仅外观变化用 `invalidate` |
| 触摸事件分发 | `dispatchTouchEvent` → `onInterceptTouchEvent` → `onTouchEvent`；类似 DOM 捕获/冒泡 |
| 自定义 View | 继承 View 重写 `onDraw`；用 Canvas + Paint 绘制 |
| 协程替代 Handler | `lifecycleScope.launch` + `delay` 更简洁；自动在主线程恢复 |
