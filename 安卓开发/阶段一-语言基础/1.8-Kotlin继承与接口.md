# 1.8 Kotlin 继承与接口

> 掌握 Kotlin 的 open/abstract 修饰符、接口默认实现和接口委托。

---

## 一、继承

### Kotlin 类默认是 final 的

与 Java 不同，Kotlin 的类默认不能被继承，方法也默认不能被重写。需要显式用 `open` 修饰：

```kotlin
// 父类必须加 open
open class Animal(val name: String) {
    // 可被重写的方法也必须加 open
    open fun sound() = "某种叫声"

    // 不加 open 的方法不能被重写
    fun description() = "这是一只$name"
}

// 子类用 : 代替 extends
class Dog(name: String) : Animal(name) {
    // 重写必须加 override
    override fun sound() = "汪汪汪"
}
```

### 为什么默认 final？

Kotlin 的设计哲学是"不轻易允许继承"，因为继承是强耦合关系。如果你没有明确设计一个类要被继承，就不应该被继承。这避免了 Java 中常见的脆弱基类问题。

### 调用父类方法

```kotlin
open class Animal(val name: String) {
    open fun sound() = "叫声"
}

class Dog(name: String) : Animal(name) {
    override fun sound(): String {
        val base = super.sound()   // 调用父类实现
        return "$base → 汪汪汪"
    }
}
```

## 二、抽象类

```kotlin
abstract class Shape(val color: String) {
    // 抽象方法 — 子类必须实现
    abstract fun area(): Double

    // 具体方法 — 子类可以直接用
    fun describe() = "$color 的图形，面积 = ${area()}"
}

class Circle(color: String, private val radius: Double) : Shape(color) {
    override fun area() = Math.PI * radius * radius
}

// 使用
val circle = Circle("红色", 5.0)
println(circle.describe())  // 红色 的图形，面积 = 78.539...
```

> 抽象类本身不需要 `open`（抽象类天然可以被继承），抽象方法也不需要 `open`。

## 三、接口

### 基本接口

```kotlin
interface Clickable {
    fun onClick()                  // 抽象方法
    fun onLongClick() {            // 默认实现（Java 8 也有）
        println("长按了")
    }
}

class Button : Clickable {
    override fun onClick() {       // 必须实现
        println("按钮被点击")
    }
    // onLongClick 可以不重写，使用默认实现
}
```

### 接口中的属性

```kotlin
interface Named {
    val name: String          // 抽象属性 — 实现类必须提供
    val displayName: String   // 可以提供 getter 作为默认实现
        get() = name
}

class User(override val name: String) : Named {
    // name 由主构造函数提供
    // displayName 使用接口默认实现
}
```

### 实现多个接口

```kotlin
interface Flyable {
    fun fly() { println("飞行中") }
}

interface Swimmable {
    fun swim() { println("游泳中") }
}

class Duck : Flyable, Swimmable {
    // 两个接口的默认实现都自动获得
}

val duck = Duck()
duck.fly()    // 飞行中
duck.swim()   // 游泳中
```

### 解决默认方法冲突

当两个接口有同名默认方法时：

```kotlin
interface A {
    fun hello() { println("A") }
}

interface B {
    fun hello() { println("B") }
}

class C : A, B {
    // 必须显式重写，指定用哪个
    override fun hello() {
        super<A>.hello()  // 选择 A 的实现
        // super<B>.hello()  // 或选择 B 的实现
        // 或者自己写全新实现
    }
}
```

## 四、接口委托（by）

**委托模式**：将接口的实现交给另一个对象处理，避免样板代码。

### 基本委托

```kotlin
interface ClickListener {
    fun onClick()
    fun onLongClick()
}

// 具体的点击处理器
class DefaultClickListener : ClickListener {
    override fun onClick() { println("默认点击") }
    override fun onLongClick() { println("默认长按") }
}

// Button 把 ClickListener 委托给 DefaultClickListener
class Button(listener: ClickListener) : ClickListener by listener

// 使用
val listener = DefaultClickListener()
val button = Button(listener)
button.onClick()     // 默认点击（委托给 listener）
```

### 部分委托 + 部分重写

```kotlin
class Button(listener: ClickListener) : ClickListener by listener {
    // 只重写需要自定义的方法
    override fun onLongClick() {
        println("自定义长按行为")
    }
    // onClick 仍然委托给 listener
}
```

### 前端类比

```typescript
// 类似装饰器模式或组合模式
class Button {
    private listener: ClickListener;
    constructor(listener: ClickListener) {
        this.listener = listener;
    }
    onClick() { this.listener.onClick(); }  // 手动委托
}
// Kotlin 的 by 关键字自动帮你做这件事
```

### 委托的实际应用

```kotlin
// Android 中常见：ViewModel 继承接口，委托给 Repository
interface UserRepository {
    fun getUser(id: String): User
    fun saveUser(user: User)
}

class RemoteUserRepository : UserRepository {
    override fun getUser(id: String) = api.fetchUser(id)
    override fun saveUser(user: User) = api.saveUser(user)
}

class UserViewModel(repo: UserRepository) : UserRepository by repo {
    // ViewModel 自动拥有 getUser 和 saveUser
    // 还可以添加自己的逻辑
}
```

## 五、类型检查与智能转换

```kotlin
open class Animal
class Dog : Animal() { fun bark() = "汪" }
class Cat : Animal() { fun meow() = "喵" }

fun handle(animal: Animal) {
    // is 检查后自动智能转换
    if (animal is Dog) {
        println(animal.bark())  // 不需要手动转换，编译器知道这里是 Dog
    }

    // when 中也能智能转换
    when (animal) {
        is Dog -> println(animal.bark())
        is Cat -> println(animal.meow())
    }
}
```

## 六、可见性修饰符

| 修饰符 | 类成员 | 顶层声明 |
|--------|--------|----------|
| `public`（默认） | 所有地方可见 | 所有地方可见 |
| `private` | 只在类内可见 | 只在文件内可见 |
| `protected` | 类内 + 子类可见 | 不适用于顶层 |
| `internal` | 同一模块内可见 | 同一模块内可见 |

> **与 Java 的区别**：Kotlin 默认 `public`（Java 默认包私有），新增了 `internal`（模块级可见）。
