# 1.16 资源管理

> 理解 Android res 目录的结构和各类资源的使用方式。

## 一、res 目录结构

```
res/
├── drawable/          图片和矢量图形
│   ├── icon.png       位图
│   ├── bg_shape.xml   形状（类似 CSS 背景）
│   └── ic_arrow.xml   矢量图（VectorDrawable）
│
├── layout/            布局文件（XML）
│   ├── activity_main.xml
│   ├── fragment_home.xml
│   └── item_list.xml
│
├── values/            值资源
│   ├── strings.xml    字符串
│   ├── colors.xml     颜色
│   ├── dimens.xml     尺寸
│   ├── styles.xml     样式
│   └── themes.xml     主题
│
├── mipmap/            应用图标（不同分辨率）
│   ├── mipmap-mdpi/
│   ├── mipmap-hdpi/
│   ├── mipmap-xhdpi/
│   ├── mipmap-xxhdpi/
│   └── mipmap-xxxhdpi/
│
├── raw/               原始文件（音频、视频等）
│   └── notification.mp3
│
└── xml/               XML 配置文件
    └── preferences.xml
```

### 前端类比

```
Android 资源               前端项目
───────────               ──────────
res/layout/*.xml      ≈   *.vue / *.jsx（模板）
res/values/strings.xml ≈  locales/zh-CN.json（国际化）
res/values/colors.xml ≈   theme.css / CSS 变量
res/values/styles.xml ≈   全局样式 / CSS 类
res/drawable/         ≈   assets/images/
res/mipmap/           ≈   public/icons/（多尺寸 favicon）
```

## 二、字符串资源

### 定义

```xml
<!-- res/values/strings.xml -->
<resources>
    <string name="app_name">我的应用</string>
    <string name="welcome">欢迎, %1$s! 你有 %2$d 条消息</string>
    <string name="multi_line">第一行\n第二行</string>
</resources>
```

### 使用

```kotlin
// 代码中使用
val appName = getString(R.string.app_name)
val welcome = getString(R.string.welcome, "张三", 5)  // 欢迎, 张三! 你有 5 条消息

// XML 布局中使用
// <TextView android:text="@string/app_name" />
```

## 四、尺寸资源

### 单位说明

| 单位 | 说明 | 使用场景 |
|------|------|----------|
| `dp` (density-independent pixels) | 密度无关像素 | 大部分尺寸（宽高、边距） |
| `sp` (scale-independent pixels) | 缩放无关像素 | 字体大小（跟随系统字体缩放） |
| `px` | 实际像素 | 不推荐使用 |

### 定义

```xml
<!-- res/values/dimens.xml -->
<resources>
    <dimen name="margin_small">8dp</dimen>
    <dimen name="margin_medium">16dp</dimen>
    <dimen name="margin_large">24dp</dimen>
    <dimen name="text_size_body">14sp</dimen>
    <dimen name="text_size_title">20sp</dimen>
</resources>
```

### 使用

```kotlin
// 代码中
val margin = resources.getDimensionPixelSize(R.dimen.margin_medium)

// XML 中
// android:layout_margin="@dimen/margin_medium"
// android:textSize="@dimen/text_size_body"
```

## 五、样式和主题

### 样式（Style）— 类似 CSS 类

```xml
<!-- res/values/styles.xml -->
<style name="TitleText">
    <item name="android:textSize">20sp</item>
    <item name="android:textColor">@color/text_primary</item>
    <item name="android:fontFamily">sans-serif-medium</item>
</style>

<style name="BodyText">
    <item name="android:textSize">14sp</item>
    <item name="android:textColor">@color/text_secondary</item>
    <item name="android:lineSpacingExtra">4dp</item>
</style>
```

```xml
<!-- XML 中使用 -->
<TextView
    style="@style/TitleText"
    android:text="标题" />
```

### 样式继承

```xml
<!-- 继承 TitleText 并覆盖颜色 -->
<style name="TitleText.Warning">
    <item name="android:textColor">@color/error</item>
</style>
```

### 主题（Theme）— 全局样式

```xml
<!-- res/values/themes.xml -->
<style name="AppTheme" parent="Theme.MaterialComponents.Light.DarkActionBar">
    <item name="colorPrimary">@color/primary</item>
    <item name="colorPrimaryDark">@color/primary_dark</item>
    <item name="colorAccent">@color/accent</item>
    <item name="android:windowBackground">@color/background</item>
</style>
```

```xml
<!-- AndroidManifest.xml 中应用主题 -->
<application
    android:theme="@style/AppTheme">
```

## 六、Drawable 资源

### Shape（形状）

```xml
<!-- res/drawable/bg_rounded.xml -->
<shape xmlns:android="http://schemas.android.com/apk/res/android"
    android:shape="rectangle">
    <solid android:color="#FFFFFF" />
    <corners android:radius="12dp" />
    <stroke android:width="1dp" android:color="#E0E0E0" />
</shape>
```

```xml
<!-- 使用 -->
<View
    android:background="@drawable/bg_rounded" />
```

> **前端类比**：Shape ≈ CSS 的 `background`, `border-radius`, `border`。

### Selector（状态选择器）

```xml
<!-- res/drawable/btn_selector.xml -->
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item android:state_pressed="true" android:drawable="@color/primary_dark" />
    <item android:state_enabled="false" android:drawable="@color/gray" />
    <item android:drawable="@color/primary" />
</selector>
```

> **前端类比**：Selector ≈ CSS 的 `:hover`, `:active`, `:disabled` 伪类。

### Layer List（图层叠加）

```xml
<!-- res/drawable/bg_shadow.xml -->
<layer-list xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- 阴影层 -->
    <item android:top="2dp">
        <shape>
            <solid android:color="#20000000" />
            <corners android:radius="8dp" />
        </shape>
    </item>
    <!-- 内容层 -->
    <item android:bottom="2dp">
        <shape>
            <solid android:color="#FFFFFF" />
            <corners android:radius="8dp" />
        </shape>
    </item>
</layer-list>
```

## 九、R 类详解

### 什么是 R 类？

`R 类`（R = Resource）是 Android 构建工具 **AAPT**（Android Asset Packaging Tool）在编译时**自动生成**的一个 Java/Kotlin 类，它包含了项目中所有资源的整数 ID 常量。你在 `res/` 目录下添加的每一个资源文件、每一个 XML 中定义的 `name` 属性，都会在 R 类中生成一个对应的 `int` 常量。

```kotlin
// R 类的本质（自动生成的伪代码）
public final class R {
    public static final class string {
        public static final int app_name = 0x7f0a0001;       // 对应 strings.xml 中的 name="app_name"
        public static final int welcome = 0x7f0a0002;
    }
    public static final class layout {
        public static final int activity_main = 0x7f0b0001;  // 对应 activity_main.xml
    }
    public static final class id {
        public static final int user_name_text = 0x7f080001; // 对应 @+id/user_name_text
    }
    public static final class drawable {
        public static final int icon = 0x7f060001;           // 对应 drawable/icon.png
    }
    public static final class color {
        public static final int primary = 0x7f040001;        // 对应 colors.xml 中的 name="primary"
    }
    // ... 还有 dimen, style, anim, menu, raw, xml, bool, integer, array 等
}
```

> **前端类比**：R 类 ≈ Webpack/Vite 的模块 ID 系统。前端 `import icon from './icon.png'` 时，构建工具会给资源分配一个可引用的标识（URL 或 hash）。Android 中 R 类做的就是这个事——每个资源分配一个 `int` ID，代码通过 ID 引用资源。

### R 类的内部子类

R 类按资源类型划分为多个**内部类**，每个内部类包含该类型的所有资源 ID：

| 内部类 | 对应资源目录/文件 | 示例 |
|--------|-------------------|------|
| `R.string` | `res/values/strings.xml` | `R.string.app_name` |
| `R.layout` | `res/layout/*.xml` | `R.layout.activity_main` |
| `R.id` | XML 中的 `@+id/xxx` | `R.id.recycler_view` |
| `R.drawable` | `res/drawable/` | `R.drawable.icon` |
| `R.color` | `res/values/colors.xml` | `R.color.primary` |
| `R.dimen` | `res/values/dimens.xml` | `R.dimen.margin_medium` |
| `R.style` | `res/values/styles.xml` | `R.style.AppTheme` |
| `R.mipmap` | `res/mipmap-*/` | `R.mipmap.ic_launcher` |
| `R.anim` | `res/anim/` 或 `res/animator/` | `R.anim.fade_in` |
| `R.menu` | `res/menu/` | `R.menu.main_menu` |
| `R.raw` | `res/raw/` | `R.raw.notification` |
| `R.xml` | `res/xml/` | `R.xml.preferences` |
| `R.array` | `res/values/arrays.xml` | `R.array.planets` |
| `R.bool` | `res/values/bools.xml` | `R.bool.is_tablet` |
| `R.integer` | `res/values/integers.xml` | `R.integer.max_count` |
| `R.plurals` | `res/values/strings.xml` | `R.plurals.song_count` |
| `R.attr` | `res/values/attrs.xml` | 自定义属性 ID |
| `R.styleable` | `res/values/attrs.xml` | 自定义属性组 |

### 在代码中使用 R 类

```kotlin
class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 1. 加载布局 → 引用 R.layout
        setContentView(R.layout.activity_main)

        // 2. 查找视图 → 引用 R.id
        val textView = findViewById<TextView>(R.id.title_text)
        val button = findViewById<Button>(R.id.submit_button)

        // 3. 设置文字 → 引用 R.string
        textView.text = getString(R.string.app_name)

        // 4. 设置颜色 → 引用 R.color
        textView.setTextColor(ContextCompat.getColor(this, R.color.primary))

        // 5. 设置图片 → 引用 R.drawable
        val icon = ContextCompat.getDrawable(this, R.drawable.icon)
        imageView.setImageDrawable(icon)

        // 6. 加载动画 → 引用 R.anim
        val animation = AnimationUtils.loadAnimation(this, R.anim.fade_in)
        textView.startAnimation(animation)
    }
}
```

### 在 XML 中引用资源

XML 中使用 `@资源类型/资源名` 的语法引用，**不需要**写 `R.`：

```xml
<!-- @string/xxx → 引用 R.string.xxx -->
<TextView android:text="@string/app_name" />

<!-- @color/xxx → 引用 R.color.xxx -->
<TextView android:textColor="@color/primary" />

<!-- @drawable/xxx → 引用 R.drawable.xxx -->
<View android:background="@drawable/bg_rounded" />

<!-- @dimen/xxx → 引用 R.dimen.xxx -->
<View android:layout_margin="@dimen/margin_medium" />

<!-- @style/xxx → 引用 R.style.xxx -->
<TextView style="@style/TitleText" />

<!-- @+id/xxx → 创建新 ID 并在 R.id 中生成常量 -->
<TextView android:id="@+id/title_text" />

<!-- @id/xxx → 引用已存在的 R.id.xxx -->
<RelativeLayout>
    <TextView android:id="@+id/title" />
    <TextView android:layout_below="@id/title" />   <!-- 引用上面的 ID -->
</RelativeLayout>
```

**`@+id` 与 `@id` 的区别**：
- `@+id/xxx`：创建新资源 ID，如果 R.id 中不存在就生成一个新的
- `@id/xxx`：引用已存在的 ID，不会创建新的

### 资源 ID 的数值含义

R 类中的 ID 是十六进制整数，结构如下：

```
0x7f0a0001
  │ │ │ └── 资源序号（Entry Index）：该类型下的第几个资源
  │ │ └──── 资源类型（Type Index）：string=0x0a, layout=0x0b, drawable=0x06...
  │ └────── 包索引（Package Index）：0x01=应用包，0x7f=当前模块
  └──────── 固定前缀
```

> **注意**：这些数值是构建时动态生成的，不同构建之间可能不同，**绝不能硬编码**。始终通过 `R.type.name` 引用。

### 多模块中的 R 类

在多模块项目中，**每个模块都有自己的 R 类**：

```
com.kugou.fanxing.R              ← app 模块的 R 类（合并所有子模块资源）
com.kugou.fanxing.module.home.R  ← module_home 模块的 R 类
com.kugou.fanxing.lib_base.R     ← lib_base 模块的 R 类
```

```kotlin
// module_home 中默认导入的是本模块的 R
import com.kugou.fanxing.module.home.R

// 可以使用本模块资源
setContentView(R.layout.fragment_home)

// 使用 app 模块的资源（需要显式指定包名）
val color = ContextCompat.getColor(this, com.kugou.fanxing.R.color.primary)

// 使用 lib_base 的资源
val icon = ContextCompat.getDrawable(this, com.kugou.fanxing.lib_base.R.drawable.icon)
```

> **前端类比**：多模块 R 类 ≈ Monorepo 中各 package 的命名空间。`@myapp/core` 和 `@myapp/home` 各有自己的导出，跨包引用需要写完整的包名。

**模块资源合并规则**：
- 最终 APK 中，app 模块的 R 类会**合并**所有依赖模块的资源 ID
- 子模块资源 ID 同时存在于子模块 R 类和 app 的 R 类中
- 如果不同模块有同名的资源（如都有 `R.string.app_name`），会产生冲突，需用前缀区分

### 动态获取资源 ID

某些场景需要根据字符串动态查找资源：

```kotlin
// 根据名字动态获取资源 ID
// 等价于 R.drawable.icon_1, R.drawable.icon_2 ...
for (i in 1..10) {
    val resId = resources.getIdentifier("icon_$i", "drawable", packageName)
    if (resId != 0) {
        // 资源存在，可以使用
        val drawable = ContextCompat.getDrawable(this, resId)
    }
}

// 注意：getIdentifier() 使用反射，性能较差，不要在循环或高频调用中使用
// 推荐做法：提前建立映射表
val iconMap = mapOf(
    "home" to R.drawable.icon_home,
    "search" to R.drawable.icon_search,
    "profile" to R.drawable.icon_profile,
)
val icon = iconMap[tabName]  // O(1) 查找
```

### 系统资源 vs 应用资源

Android 框架本身也提供了大量内置资源，通过 `android.R` 访问：

```kotlin
// 应用资源（你自己的）
R.string.app_name              // res/values/strings.xml 中定义
R.layout.activity_main         // res/layout/ 中定义
R.color.primary                // res/values/colors.xml 中定义

// 系统资源（Android 框架内置）
android.R.string.ok            // 系统内置的 "OK" 文字
android.R.string.cancel        // 系统内置的 "Cancel" 文字
android.R.drawable.ic_menu_search   // 系统搜索图标
android.R.color.black          // 系统黑色
android.R.layout.simple_list_item_1 // 系统内置列表项布局
```

```kotlin
// 如果 import 了 android.R，会覆盖应用 R 类，导致编译错误
// import android.R  ← 不要这样做！

// 需要同时使用时，用完整包名区分
val appName = getString(com.kugou.fanxing.R.string.app_name)  // 应用资源
val okText = getString(android.R.string.ok)                    // 系统资源
```

### 常见问题与注意事项

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `R.xxx 找不到` / 红色报错 | 资源文件有语法错误，R 类生成失败 | 检查 XML 文件是否有标签未闭合、属性拼写错误 |
| `R.layout.xxx` 不在提示中 | 新建的 XML 还没编译 | Build → Make Project 触发 R 类重新生成 |
| `import android.R` 导致报错 | 导入了系统 R 类，覆盖了应用 R 类 | 删除 `import android.R`，确保 import 自己包名的 R |
| 资源 ID 冲突 | 多模块存在同名资源 | 给资源名加模块前缀，如 `home_title`、`player_title` |
| `@+id` 写成 `@id` | 引用了尚未定义的 ID | 首次声明用 `@+id/xxx`，之后引用用 `@id/xxx` |

### R 类生成流程

```
                    ┌─────────────────┐
                    │  res/ 目录下所有资源  │
                    │  + AndroidManifest  │
                    └────────┬──────────┘
                             │
                    ┌────────▼──────────┐
                    │  AAPT2 编译资源     │
                    │  (Gradle 构建阶段)  │
                    └────────┬──────────┘
                             │
                    ┌────────▼──────────┐
                    │  生成 R.java 文件    │
                    │  (build/generated/) │
                    └────────┬──────────┘
                             │
                    ┌────────▼──────────┐
                    │  编译为 R.class     │
                    │  (Kotlin/Java 可用) │
                    └───────────────────┘
```

生成的 R 文件位于：`app/build/generated/source/r/debug/包名/R.java`

> **注意**：`build/` 目录是自动生成的，不应该提交到 Git。`.gitignore` 中已排除此目录。如果 R 类出问题，Clean Project 后 Rebuild 即可重新生成。

## 十、ViewBinding（bind 类）

### 什么是 ViewBinding？

ViewBinding 是 Android 构建工具为**每个 XML 布局文件**自动生成的一个**绑定类**，让你可以用类型安全的方式访问布局中的所有 View，不再需要手写 `findViewById`。

### 为什么用它替代 `findViewById`？

| 对比项 | `findViewById` | ViewBinding |
|--------|---------------|-------------|
| 类型安全 | 需要手动指定泛型，可能强转错误 | 自动推断正确类型 |
| Null 安全 | 可能返回 null，运行时崩溃 | 非 `@Nullable` 的 View 保证非空 |
| 拼写错误 | `R.id.xxx` 拼错 → 运行时 null | 拼错 → **编译时报错** |
| 代码量 | 每个 View 都要写一行 | 一次绑定，全部可用 |
| 前端类比 | `document.getElementById('xxx')` | Vue 的 `ref` / React 的 `useRef` |

### 启用 ViewBinding

在模块的 `build.gradle`（或 `build.gradle.kts`）中添加：

```groovy
// build.gradle (Groovy)
android {
    ...
    viewBinding {
        enable = true
    }
}
```

```kotlin
// build.gradle.kts (Kotlin DSL)
android {
    ...
    buildFeatures {
        viewBinding = true
    }
}
```

### Binding 类的命名规则

构建工具根据 XML 文件名自动生成类名，规则为：**去掉下划线，转大驼峰，加 `Binding` 后缀**：

```
XML 文件名                     生成的 Binding 类
─────────────                  ─────────────────
activity_main.xml          →   ActivityMainBinding
fragment_home.xml          →   FragmentHomeBinding
item_song_list.xml         →   ItemSongListBinding
dialog_confirm.xml         →   DialogConfirmBinding
include_toolbar.xml        →   IncludeToolbarBinding
```

### 在 Activity 中使用

```xml
<!-- res/layout/activity_main.xml -->
<LinearLayout ...>
    <TextView
        android:id="@+id/tv_title"
        android:text="标题" />

    <Button
        android:id="@+id/btn_submit"
        android:text="提交" />
</LinearLayout>
```

```kotlin
class MainActivity : AppCompatActivity() {

    // 1. 声明 binding 变量
    private lateinit var binding: ActivityMainBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 2. inflate 布局，替代 setContentView(R.layout.xxx)
        binding = ActivityMainBinding.inflate(layoutInflater)
        setContentView(binding.root)

        // 3. 直接通过 binding 访问 View，无需 findViewById
        binding.tvTitle.text = "新的标题"
        binding.btnSubmit.setOnClickListener {
            println("按钮被点击")
        }

        // binding.tvTitle  → 类型是 TextView，不是 View!
        // binding.btnSubmit → 类型是 Button，不是 View!
        // 编译器已经知道每个属性的正确类型
    }
}
```

### 在 Fragment 中使用

Fragment 的 View 生命周期和 Fragment 本身不同，需要在 `onDestroyView` 中释放 binding：

```kotlin
class HomeFragment : Fragment() {

    // Fragment 中用可空类型，因为 View 可能被销毁
    private var _binding: FragmentHomeBinding? = null

    // 非空 accessor，只在 onCreateView 和 onDestroyView 之间安全使用
    private val binding get() = _binding!!

    override fun onCreateView(
        inflater: LayoutInflater,
        container: ViewGroup?,
        savedInstanceState: Bundle?
    ): View {
        // inflate 布局
        _binding = FragmentHomeBinding.inflate(inflater, container, false)
        return binding.root
    }

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        // 使用 binding 访问 View
        binding.tvTitle.text = "首页"
        binding.btnRefresh.setOnClickListener {
            // 刷新逻辑
        }
    }

    override fun onDestroyView() {
        super.onDestroyView()
        // 必须置 null，防止内存泄漏
        _binding = null
    }
}
```

> **为什么 Fragment 要用 `_binding?` + `binding` 双属性模式？**
> Fragment 的 View 可以被销毁后重建（比如回退栈），如果直接用 `lateinit var` 会在 View 销毁后访问到已失效的 View，导致崩溃。用 `_binding = null` 安全释放，`binding` 属性仅在 View 存活期间调用。

### 在 RecyclerView Adapter 中使用

```kotlin
class SongAdapter : RecyclerView.Adapter<SongAdapter.ViewHolder>() {

    private var songs = listOf<String>()

    // ViewHolder 持有 binding
    inner class ViewHolder(
        private val binding: ItemSongListBinding
    ) : RecyclerView.ViewHolder(binding.root) {

        fun bind(song: String) {
            binding.tvSongName.text = song
        }
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): ViewHolder {
        val binding = ItemSongListBinding.inflate(
            LayoutInflater.from(parent.context),
            parent,
            false
        )
        return ViewHolder(binding)
    }

    override fun onBindViewHolder(holder: ViewHolder, position: Int) {
        holder.bind(songs[position])
    }

    override fun getItemCount() = songs.size
}
```

### include 和 merge 标签的 ViewBinding

```xml
<!-- res/layout/include_toolbar.xml -->
<LinearLayout ...>
    <TextView android:id="@+id/tv_toolbar_title" />
    <Button android:id="@+id/btn_back" />
</LinearLayout>
```

```xml
<!-- res/layout/activity_main.xml -->
<LinearLayout ...>
    <!-- include 会生成一个同名类型的 binding 属性 -->
    <include
        android:id="@+id/toolbar"
        layout="@layout/include_toolbar" />

    <TextView android:id="@+id/tv_content" />
</LinearLayout>
```

```kotlin
// 通过 binding.toolbar 访问 include 的 binding
binding.toolbar.tvToolbarTitle.text = "页面标题"
binding.toolbar.btnBack.setOnClickListener { finish() }
```

> **注意**：`<include>` 必须设置 `android:id`，否则无法通过 binding 访问。`<merge>` 标签不会生成独立 binding，其子 View 直接合并到父布局的 binding 中。

### 完整流程对比

```
┌─── 传统 findViewById 方式 ────────────────────────────────────┐
│                                                               │
│  setContentView(R.layout.activity_main)                       │
│  val tvTitle = findViewById<TextView>(R.id.tv_title)          │
│  val btnSubmit = findViewById<Button>(R.id.btn_submit)        │
│  val ivAvatar = findViewById<ImageView>(R.id.iv_avatar)       │
│  // 每新增一个 View，就要加一行 findById                         │
│  // 拼错 id → 运行时 null → 崩溃                                │
│  // 类型写错 → ClassCastException → 崩溃                       │
└───────────────────────────────────────────────────────────────┘

┌─── ViewBinding 方式 ─────────────────────────────────────────┐
│                                                               │
│  binding = ActivityMainBinding.inflate(layoutInflater)         │
│  setContentView(binding.root)                                 │
│                                                               │
│  binding.tvTitle.text = "标题"        // 类型安全，编译期检查    │
│  binding.btnSubmit.setOnClickListener { ... }                  │
│  binding.ivAvatar.setImageResource(R.drawable.avatar)         │
│  // 新增 View 后，binding 类自动更新，直接用即可                  │
│  // 拼错属性名 → 编译报错，不会运行时崩溃                         │
└───────────────────────────────────────────────────────────────┘
```

## 本章知识点总结

| 知识点 | 要点 |
|--------|------|
| res 目录结构 | `drawable`（图形）/ `layout`（布局）/ `values`（值）/ `mipmap`（图标）/ `raw`（原始文件） |
| 字符串资源 | `strings.xml` 定义；`%1$s`/`%2$d` 格式化参数；支持国际化 |
| 颜色资源 | `colors.xml` 定义；支持透明度（8 位十六进制） |
| 尺寸单位 | `dp` 用于布局尺寸；`sp` 用于字体大小（跟随系统缩放） |
| 样式与主题 | Style ≈ CSS 类（单个组件）；Theme ≈ 全局 CSS 变量 |
| Shape | XML 定义形状（矩形/圆角/渐变等）；≈ CSS `border-radius` + `background` |
| Selector | 状态选择器（pressed/enabled/focused）；≈ CSS 伪类 |
| 屏幕适配 | 限定符目录（`values-sw600dp` 等）；系统自动选择最匹配资源 |
| R 类 | AAPT 自动生成的资源 ID 常量类；按类型分为 R.string/R.layout/R.id 等内部类；多模块各有独立 R 类；`android.R` 为系统内置资源 |
| ViewBinding | 构建工具为每个 XML 布局自动生成 Binding 类；替代 `findViewById`，类型安全 + null 安全 + 编译期检查；Activity 用 `inflate` + `setContentView(binding.root)`；Fragment 用 `_binding?` 双属性模式防内存泄漏 |
