# 3.2 线程处理

> 掌握 Android 的线程模型、线程池和 Kotlin 协程。

---

## 一、Android 线程模型

### 基本规则

1. **主线程（UI 线程）**：负责处理 UI 事件和绘制，不能执行耗时操作
2. **子线程**：执行耗时操作（网络、数据库、文件 IO）
3. **UI 操作只能在主线程执行**，子线程更新 UI 会崩溃

### 前端类比

```
Android                        JavaScript
───────                        ──────────
主线程                     ≈   单线程（事件循环）
子线程                     ≈   Web Worker
Handler.post {}            ≈   requestAnimationFrame / setTimeout
协程 + Dispatchers.IO      ≈   Worker 执行耗时计算
协程 + Dispatchers.Main    ≈   回到主线程
```

## 二、Thread 基础

```kotlin
// 方式 1：Thread 类
Thread {
    // 子线程代码
    val data = heavyWork()
}.start()

// 方式 2：Runnable
Thread(Runnable {
    val data = heavyWork()
}).start()

// 方式 3：Kotlin 简写
thread {
    val data = heavyWork()
}
```

### 切回主线程

```kotlin
thread {
    val data = heavyWork()
    // 方式 1：Handler
    Handler(Looper.getMainLooper()).post {
        textView.text = data
    }

    // 方式 2：Activity 的 runOnUiThread
    runOnUiThread {
        textView.text = data
    }

    // 方式 3：View 的 post
    textView.post {
        textView.text = data
    }
}
```

## 三、线程池

频繁创建线程开销大，线程池可以复用线程：

```kotlin
// 固定大小线程池
val executor = Executors.newFixedThreadPool(4)

// 缓存线程池（适合大量短任务）
val cacheExecutor = Executors.newCachedThreadPool()

// 单线程池（适合需要顺序执行的任务）
val singleExecutor = Executors.newSingleThreadExecutor()

// IO 密集型线程池（Kotlin 协程默认使用）
val ioExecutor = Executors.newFixedThreadPool(Runtime.getRuntime().availableProcessors() * 2)

// 使用
executor.execute {
    val data = heavyWork()
    runOnUiThread {
        updateUI(data)
    }
}

// 关闭线程池
executor.shutdown()
```

### 自定义 ThreadPoolExecutor

```kotlin
val executor = ThreadPoolExecutor(
    2,                      // 核心线程数
    4,                      // 最大线程数
    30, TimeUnit.SECONDS,   // 空闲线程存活时间
    LinkedBlockingQueue(128), // 任务队列
    ThreadFactory { r -> Thread(r, "MyThread-${System.currentTimeMillis()}") }
)
```

## 四、Kotlin 协程（推荐）

协程是 Kotlin 处理异步操作的推荐方式，比线程更轻量。

### 核心概念

| 概念 | 说明 |
|------|------|
| `CoroutineScope` | 协程作用域，管理协程生命周期 |
| `launch` | 启动一个协程（不返回结果） |
| `async` | 启动一个协程（返回结果） |
| `suspend` | 标记挂起函数（可在协程中暂停和恢复） |
| `Dispatchers` | 调度器，决定协程在哪个线程执行 |
| `withContext` | 切换协程的执行线程 |

### Dispatchers（调度器）

```kotlin
Dispatchers.Main     // 主线程（UI 操作）
Dispatchers.IO       // IO 线程池（网络、文件、数据库）
Dispatchers.Default  // 计算线程池（CPU 密集型任务）
```

### 基本使用

```kotlin
// 在 ViewModel 中
class UserViewModel : ViewModel() {

    fun loadUser() {
        // 启动协程
        viewModelScope.launch {
            // 切到 IO 线程执行网络请求
            val user = withContext(Dispatchers.IO) {
                apiService.getUser()
            }
            // 自动回到主线程
            _userState.value = UiState.Success(user)
        }
    }
}

// 在 Activity/Fragment 中
lifecycleScope.launch {
    val data = withContext(Dispatchers.IO) {
        fetchData()
    }
    textView.text = data
}
```

### suspend 函数

```kotlin
// suspend 标记的函数可以在协程中暂停和恢复
suspend fun fetchUser(): User {
    delay(1000)  // 模拟耗时（不阻塞线程）
    return User("张三", 25)
}

// 调用 suspend 函数必须在协程中
viewModelScope.launch {
    val user = fetchUser()  // 在这里暂停 1 秒，不阻塞主线程
    println(user)
}
```

> **前端类比**：`suspend fun` ≈ `async function`，`delay()` ≈ `await sleep()`，但协程不阻塞线程。

### async 并发

```kotlin
viewModelScope.launch {
    // 两个请求并发执行
    val deferredUser = async { apiService.getUser() }
    val deferredSongs = async { apiService.getSongs() }

    // 等待两个结果
    val user = deferredUser.await()
    val songs = deferredSongs.await()

    // 使用结果
    updateUI(user, songs)
}
```

> **前端类比**：`async + await` ≈ `Promise.all([fetch1(), fetch2()])`。

### 异常处理

```kotlin
viewModelScope.launch {
    try {
        val user = withContext(Dispatchers.IO) {
            apiService.getUser()
        }
        _state.value = Success(user)
    } catch (e: IOException) {
        _state.value = Error("网络错误")
    } catch (e: HttpException) {
        _state.value = Error("服务器错误: ${e.code}")
    } catch (e: Exception) {
        _state.value = Error("未知错误")
    }
}
```

### Flow（数据流）

```kotlin
// 冷流 — 有订阅者时才发射数据
fun getUsers(): Flow<List<User>> = flow {
    val users = apiService.getUsers()
    emit(users)  // 发射数据
}

// 收集数据
viewModelScope.launch {
    getUsers().collect { users ->
        _userList.value = users
    }
}

// StateFlow — 热流，持有最新状态（用于 ViewModel）
private val _state = MutableStateFlow<UiState>(UiState.Loading)
val state: StateFlow<UiState> = _state.asStateFlow()

// Flow 操作符
getUsers()
    .map { users -> users.filter { it.isVip } }
    .distinctUntilChanged()
    .catch { e -> emit(emptyList()) }
    .collect { vipUsers -> updateList(vipUsers) }
```

> **前端类比**：`Flow` ≈ RxJS Observable，`StateFlow` ≈ BehaviorSubject（保存最新值），`collect` ≈ `subscribe`。

## 五、协程 vs 线程

| 对比 | 协程 | 线程 |
|------|------|------|
| 创建成本 | 极低（几字节） | 高（约 1MB 栈空间） |
| 切换成本 | 用户态切换，极低 | 内核态切换，较高 |
| 数量 | 可以创建数万个 | 通常几百个就很多了 |
| 取消 | `job.cancel()` 轻松取消 | 需要中断标志位配合 |
| 异常处理 | try-catch 原生支持 | 需要 Handler 传递 |
