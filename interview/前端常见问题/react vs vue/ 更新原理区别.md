## 区别
| 维度           | Vue（3.x）                                                    | React（18+）                                                       |
| -------------- | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| **更新触发源**   | 响应式数据的 setter 触发（数据变化直接感知）                    | setState/useState 主动调用（只感知状态更新，不感知数据内部变化）    |
| **默认更新范围** | 仅触发依赖该数据的组件/effect                                  | 从更新的组件开始，递归重渲所有子组件                                |
| **VDOM比对时机** | 仅在触发更新的 effect 中执行，比对范围极小                      | 所有重渲组件都会生成新 VDOM，全量比对                               |
| **避免无效更新** | 内置响应式追踪天然避免（数据没变不触发）                        | 需手动用 memo/useMemo/useCallback 跳过无效渲染                      |
| **更新粒度**     | 细粒度（数据级）：精准到依赖该数据的节点                      | 粗粒度（组件级）：先全量 render，再逐步比对                          |
| **心智负担**     | 低：框架自动追踪依赖，无需手动优化                            | 高：需手动保证引用不变（如 useCallback），否则子组件可能重复渲染    |

所以 vue 的性能就比react好吗？各自在什么场景下比较有优势？

| 场景类型                | Vue 3 优势点                                  | React 18 优势点                                         | 性能表现对比   |
|------------------------|-----------------------------------------------|---------------------------------------------------------|--------------|
| 中低复杂度业务页面      | 内置精准更新，无需手动优化，开发成本低         | 需手动加 memo/useCallback，否则有多余 render            | Vue 更优     |
| 高频更新场景（实时数据） | 响应式追踪轻量，结合防抖节流可优化             | 并发更新 + startTransition 避免卡顿，可控性强           | React 更优   |
| 超大列表 / 数据可视化   | 虚拟列表生态成熟，性能和 React 持平           | 虚拟列表 + 不可变数据，适合海量数据计算                  | 基本持平     |
| 超大型应用（团队协作）  | 性能优化门槛低，新手友好                      | 优化逻辑清晰（纯函数 + 不可变），适合大型团队规范        | React 更优   |

vue 效率更高，react 更加可控
