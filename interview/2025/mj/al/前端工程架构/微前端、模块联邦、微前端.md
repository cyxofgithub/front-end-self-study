## 对比

| 对比维度 | iframe                       | qiankun                        | 模块联邦                             |
| -------- | ---------------------------- | ------------------------------ | ------------------------------------ |
| 隔离性   | 天然完全隔离                 | 沙箱隔离（可配置，灵活）       | 需手动处理（CSS Modules / 命名空间） |
| 用户体验 | 割裂（路由不同步、弹窗截断） | 无缝集成（路由同步、全局弹窗） | 无缝集成（组件级复用，体验一致）     |
| 接入成本 | 极低（零改造）               | 中（子应用需导出生命周期）     | 中高（需配置 Webpack/Vite）          |
| 通信效率 | 低（仅 postMessage）         | 高（全局状态发布订阅）         | 高（直接调用远程模块）               |
| 资源复用 | 无（重复加载依赖）           | 支持公共依赖共享               | 原生支持依赖共享                     |
| 适用场景 | 嵌入第三方应用、简单静态页面 | 大型单体应用拆分为独立业务应用 | 跨应用组件复用、模块级拆分           |

## qiankun 和 micro-app 区别

| 对比维度 | qiankun                                                        | micro-app                                                     | 核心说明                                           |
| -------- | -------------------------------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------- |
| 底层架构 | 基于 single-spa，动态加载脚本、管理生命周期                    | 类 WebComponents，CustomElement + 自定义 ShadowDom            | qiankun 依赖 single-spa，micro-app 更原生组件化    |
| 接入方式 | HTML/JS Entry，子应用需导出生命周期（bootstrap/mount/unmount） | 标签化 `<micro-app name="xxx" url="xxx"></micro-app>`，零改造 | micro-app 接入成本低，qiankun 子应用需适配生命周期 |
| 样式隔离 | 可选配置（ShadowDOM/Scoped CSS），需手动开启                   | 基于 ShadowDom 天然隔离，默认开启                             | micro-app 隔离更彻底，qiankun 配置灵活但复杂       |
| JS 沙箱  | 支持 Proxy 沙箱和 Snapshot 沙箱，隔离全局变量                  | 自定义沙箱，闭包+代理隔离执行环境                             | 两者均隔离，qiankun 方案覆盖更全                   |
| 应用通信 | initGlobalState 全局状态管理、props 传递、自定义事件监听/触发  | CustomEvent、props 传递，API 更简洁                           | micro-app 通信轻量，qiankun 全局状态更强           |
| 资源加载 | import-html-entry 解析 HTML 加载资源，支持预加载               | 自动解析子应用资源，支持预加载与缓存策略                      | micro-app 加载自动化，qiankun 可自定义             |
| 生态兼容 | 兼容 React、Vue、Angular 等主流框架，社区活跃，文档完善        | 兼容主流框架，适配性略逊于 qiankun，文档较简洁                | qiankun 企业级实践多，micro-app 简单实用           |
| 学习成本 | 中等，需理解 single-spa 生命周期与沙箱机制                     | 低，标签化使用，上手快，概念简单                              | micro-app 适合上手，qiankun 支持深度定制           |
| 适用场景 | 大型后台系统、多团队协作、遗留系统渐进式迁移                   | 中小型、敏捷交付、跨团队轻量协作、快速集成需求                | qiankun 适合复杂大项目，micro-app 适合轻量快速集成 |

## qiankun 原理

1. HTML Entry 资源加载机制：跟 microApp 差不多，解析 html 提取 script、link、style 标签、加载 css 资源注入到主应用中、js 资源在沙箱中执行
2. JS 沙箱机制（解决 “全局变量污染”），有两种：
    - 1.跟 microApp 原理类似用 proxy
    - 2.快照沙箱（兼容不支持 proxy 浏览器），在应用挂载前备份当前 window，子应用运行时，允许修改 window，子应用卸载时，恢复 window 到备份状态。
3. 样式隔离机制（解决 “CSS 污染”）

    - Shadow DOM 隔离（推荐）、天然支持隔离
    - Scoped CSS 隔离（兼容）、就是加样式前缀

4. 应用通信机制（解决 “主 / 子应用怎么传数据”）

    - 基于发布 - 订阅模式，创建一个全局的状态容器，主 / 子应用都可以监听、修改状态；
    - 注册子应用时，通过 props 传递数据，子应用在生命周期函数中接收
