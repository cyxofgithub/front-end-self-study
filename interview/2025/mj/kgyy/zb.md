## 简历可能问的问题

### 负责的低代码模块核心架构是什么？组件库如何封装？表单配置化是如何实现的？

我负责的是插件模块，位于低代码的拓展层，我们整个低代码技术架构分成数据模型层、渲染层、编辑层、扩展层，我所涉及参与的就是扩展层

具体涉及到到内容就是属属性面板插件、属性设置器等扩展能力，如何把抽象定义和相关配置转换成真实渲染的面板和对应的属性设置器，怎么去减少重复的工作和开发效率以及一些定制化的需求

### 低代码性能优化

-   加载策略，全量加载、按需加载
-   渲染端与编辑端资源分离，避免不必要的代码加载

### 低代码平台的性能瓶颈如何解决？

这个其实要具体问题具体分析，像我们比较常见的问题一个是包体问题、一个是重复的渲染问题（适当去用一些防抖、节流、缓存、建立批量更新机制）

### 遇到的最大困难

在实现数据处理流程图模块时，主要遇到四类挑战：

1. 技术预研与选型
   首次接触流程图编辑器，需要从零开始选型。调研了 React Flow、react-diagrams、mxGraph 等方案，对比 React 集成度、性能、可定制性，并搭建 demo 验证可行性。最终选择 React Flow，并完成技术预研。

2. 业务逻辑理解
   该模块不仅是 UI 展示，背后是完整的 SQL 处理流程。需要理解数据源、过滤、字段映射、横向连接、追加合并、分组汇总等节点的业务逻辑，以及节点间的数据流转与依赖关系

3. 交互设计与数据结构设计
   交互细节多，包括节点拖拽、连接验证、位置同步、删除处理、视图初始化等。需要与后端对齐数据结构，确定节点属性、连接关系、位置信息的存储与同步方式，确保前后端数据一致。

4. 时间管理与优先级
   有明确的交付节点，需要平衡功能完整性与时间。采用 MVP 思路，优先完成核心流程（节点创建、连接、基础验证），再逐步完善细节（视图优化、错误提示、交互优化），确保按时交付核心功能。

### react flow 的优势

1. 符合技术栈
2. 有成熟的项目做参考
3. 社区活跃，还在维护
4. 能满足现有功能（自定义节点、多节点连线）
5. 性能优势-虚拟渲染
