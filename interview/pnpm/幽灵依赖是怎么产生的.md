# 幽灵依赖是怎么产生的

## 什么是幽灵依赖

**幽灵依赖（Phantom Dependencies）** 是指项目中使用了 `package.json` 中**未声明**的依赖，但这些依赖却可以正常工作。

## 产生原因

### npm/yarn 的扁平化策略

1. **依赖提升（Hoisting）**：

    - npm/yarn 会将依赖的依赖（间接依赖）提升到 `node_modules` 根目录
    - 目的是减少嵌套层级，避免路径过长问题

2. **示例场景**：

```json
// package.json
{
    "dependencies": {
        "express": "^4.18.0"
    }
}
```

```javascript
// 代码中直接使用 express 的依赖
const cookieParser = require('cookie-parser'); // ❌ 未在 package.json 中声明
```

**为什么能工作？**

-   `express` 依赖了 `cookie-parser`
-   npm/yarn 将 `cookie-parser` 提升到 `node_modules` 根目录
-   Node.js 模块解析机制会找到它，代码可以正常运行

### 目录结构对比

**npm/yarn 的扁平化结构：**

```
node_modules/
├── express/          # 直接依赖
├── cookie-parser/    # 间接依赖，被提升到根目录 ⚠️
└── ...
```

**pnpm 的严格结构：**

```
node_modules/
├── express/          # 只有直接依赖
└── .pnpm/
    └── cookie-parser/  # 间接依赖被隔离
```

## 问题与风险

1. **版本不确定性**：

    - 间接依赖的版本由直接依赖决定
    - 直接依赖升级可能导致间接依赖版本变化
    - 代码可能突然报错

2. **依赖缺失风险**：

    - 如果直接依赖不再依赖某个包
    - 该包会被移除，代码立即报错
    - 但开发者可能不知道这个依赖的存在

3. **团队协作问题**：
    - 新成员安装依赖时可能缺少某些包
    - CI/CD 环境可能无法正常运行

## pnpm 如何解决

-   **严格的依赖隔离**：只能访问 `package.json` 中声明的依赖
-   **符号链接机制**：间接依赖不会被提升到根目录
-   **强制显式声明**：使用未声明的依赖会直接报错

## 总结

幽灵依赖的产生 = **依赖提升** + **Node.js 模块解析机制** + **缺少严格检查**

pnpm 通过**严格的依赖隔离**和**符号链接**机制，从根本上避免了幽灵依赖问题。
