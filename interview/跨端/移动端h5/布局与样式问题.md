## 移动端适配问题（不同屏幕尺寸显示错乱）

-   现象：设计稿在 iPhone 13 显示正常，在安卓大屏手机上元素被拉伸 / 挤压。
-   原因：未做响应式适配，或适配方案不合理（如直接用 px 固定尺寸）。
-   解决方案：
    -   主流方案：rem + 动态根字体大小（如基于屏幕宽度计算 html 的 font-size）；
    -   现代方案：vw/vh（1vw = 视口宽度的 1%，无需 JS 动态计算）；
    -   辅助方案：Flex/Grid 布局（弹性布局适配不同容器尺寸）。

## fixed 定位在移动端失效 / 错位

-   现象：fixed 元素在软键盘弹出后位置偏移，或在 iOS Safari 中跟随滚动。
-   原因：移动端软键盘弹出后，视口高度变化；iOS Safari 对 fixed 的渲染机制特殊（滚动时会暂时脱离 fixed）。
-   解决方案：
    -   避免 fixed 元素嵌套在 scroll 容器内；
    -   软键盘弹出时，监听 resize 事件，动态调整 fixed 元素位置；
    -   替代方案：用 sticky 定位（position: sticky）实现局部固定效果。

## 刘海屏 / 安全区适配问题

-   现象：页面内容被手机顶部刘海、底部小黑条遮挡，尤其是导航栏 / 底部按钮。
-   原因：未考虑 iOS/Android 的安全区（safe area）规则。
-   解决思路：
    -   使用 CSS 的 safe-area-inset-\* 变量适配：

```javascript
/* 底部按钮适配，避免被小黑条遮挡 */
.footer-btn {
  padding-bottom: constant(safe-area-inset-bottom); /* iOS < 11.2 */
  padding-bottom: env(safe-area-inset-bottom); /* iOS >= 11.2 */
}
/* 顶部导航适配刘海屏 */
.header {
  padding-top: constant(safe-area-inset-top);
  padding-top: env(safe-area-inset-top);
}
```

    - iOS 需额外设置视口的 viewport-fit=cover：

```javascript
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```

**为什么必须设置 cover？**

这是 viewport 不同值的效果

| 取值                 | 效果                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| contain（默认/auto） | 网页内容仅被限制在「安全区」内显示，不会覆盖刘海、底部小黑条区域，屏幕边缘会留空白       |
| cover                | 网页的视口会完全覆盖整个屏幕（包括刘海、底部小黑条所在的「非安全区」），内容可以铺满全屏 |

-   contain 虽能避免遮挡，但会导致边缘空白、空间浪费、适配不一致，不符合移动端全屏设计的核心需求；
-   cover + 安全区变量 是「兼顾功能和体验」的最优解：既利用全屏空间，又精准避开遮挡区域；
