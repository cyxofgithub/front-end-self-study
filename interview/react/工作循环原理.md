### React Fiber 架构

React Fiber 是一种重新实现的协调算法，它使得 React 可以更细粒度地控制渲染工作，从而提高应用的响应性和性能。Fiber 允许 React 将渲染工作分成多个小任务，并在每个任务之间检查主线程是否有更高优先级的任务需要处理。

### 工作循环的主要步骤

1. **任务分割**：将渲染工作分成多个小任务，每个任务处理一个或多个组件的更新。
2. **任务调度**：调度器根据任务的优先级和浏览器的空闲时间来调度任务的执行。
3. **让出主线程**：在每个任务之间，调度器会检查主线程是否有更高优先级的任务需要处理。如果有，React 会暂停当前的渲染工作，让出主线程。
4. **恢复工作**：当主线程空闲时，调度器会恢复之前暂停的渲染工作，继续处理剩余的任务。

### 示例代码

以下是一个简化的示例，演示了 React 工作循环的基本原理：

```javascript
let sum = 0;
let currentIndex = 0; // 当前遍历的索引
const totalCount = 20000000;

const getCurrentTime = () => performance.now();

const channel = new MessageChannel();
const port = channel.port2;
channel.port1.onmessage = performWorkUntilDeadline;

let frameStartTime = 0;

// 用 requestAnimationFrame 获取开始时间后再进入循环
function performWorkUntilDeadline() {
    // 利用 requestAnimationFrame 保证获取的起始时间是最新一帧
    requestAnimationFrame((rafTime) => {
        frameStartTime = rafTime;
        const hasMoreWork = workLoop(frameStartTime);

        if (hasMoreWork) {
            port.postMessage(null);
        }
    });
}

// 调度应该被中断吗
function shouldYieldToHost(startTime) {
    // React 默认每一帧只允许 5ms 的 JS 执行
    const timeElapsed = getCurrentTime() - startTime;
    return timeElapsed >= 5;
}

const workLoop = (startTime) => {
    work(startTime);
    return currentIndex < totalCount;
};

const work = (startTime) => {
    for (; currentIndex < totalCount && !shouldYieldToHost(startTime); currentIndex++) {
        sum += currentIndex;
    }
};

// 首次调度
performWorkUntilDeadline();
```

### 为什么要用 requestAnimationFrame 获取开始时间？

1. **精准同步渲染帧**
    - `requestAnimationFrame` 的回调参数 `rafTime` 是下一帧开始的精准时间戳，可以精确对齐浏览器的刷新节奏，标记每一帧的起点，便于判断“本帧还剩多少可用时间”。
2. **高于 Date.now() 的精度与可靠性**
    - `Date.now()` 仅能获取当前的系统时间，无法与渲染帧对齐，容易产生毫秒级别的偏差，影响时间切片调度的准确性。

**示例：**

```js
requestAnimationFrame((rafTime) => {
    // rafTime 即为当前帧的准确起点
});

const now = Date.now(); // now 只是系统此时的时间，不能保证与帧同步，精度不如 rafTime。
```

### 为什么用 performance.now() 获取当前时间？

因为 performance.now() 返回的是一个高精度时间戳，可以精确到毫秒级别，而 Date.now() 返回的是一个时间戳，只能精确到秒级别。

```javascript
const now = performance.now();
```

### 为什么用 MessageChannel 实现任务调度？

因为 MessageChannel 的回调会在浏览器主线程空闲时执行，所以可以保证任务调度不会阻塞主线程。并且 MessageChannel 对比 setTimeout(4ms 延迟) 延迟更低, 更适合实现时间切片和任务调度。

```javascript
const channel = new MessageChannel();
const port = channel.port2;
channel.port1.onmessage = performWorkUntilDeadline;
```

### 总结

React 的工作循环通过 React Fiber 架构实现，主要步骤包括：

1. 将渲染工作分成多个小任务。
2. 使用调度器根据任务优先级和浏览器空闲时间来调度任务。
3. 在每个任务之间检查主线程是否有更高优先级的任务需要处理。
4. 使用 MessageChannel、 requestAnimationFrame、 performance.now() 等浏览器 API 来实现时间切片和任务调度。
