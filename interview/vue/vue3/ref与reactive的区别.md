## ref与reactive的区别
| 对比维度               | ref                                                                                  | reactive                                                                                  |
|--------------------|--------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| 适用数据类型            | 支持所有类型（基本类型 + 引用类型），核心适配基本类型                                             | 仅支持引用类型（对象 / 数组 / Map / Set 等），基本类型使用会失效并控制台警告                                    |
| 访问 / 修改方式（脚本）    | 必须通过 `.value` 访问 / 修改（如 `count.value = 1`）                                  | 直接访问 / 修改属性（如 `info.address = '上海'`），无需 `.value`                                   |
| 访问 / 修改方式（模板）    | 自动解包，模板中可直接写变量名（如 `{{ count }}`），无需 `.value`                        | 直接访问属性（如 `{{ info.address }}`），无需 `.value`                                               |
| 底层响应式原理           | 基本类型：`Object.defineProperty` 劫持 value 的 get/set；<br>引用类型：内部自动调用 reactive（Proxy） | 基于 ES6 `Proxy` 代理整个对象，可监听属性新增/删除、数组索引修改等                                      |
| 解构行为                | 解构基本类型会丢失响应式；<br>解构引用类型的内部属性也会丢失响应式（需配合 `toRefs` 使用）              | 直接解构一定会丢失响应式，必须先用 `toRefs` 转换后再解构                                             |
| 核心适用场景             | 1. 单个独立的基本类型值（如计数器、开关状态等）<br>2. 组合式函数返回响应式数据                         | 1. 复杂对象 / 数组（如用户信息、列表数据等）<br>2. 一组相关的响应式数据（如表单多字段）                         |
