# 重连退避算法是怎么设计的

> **一句话结论：** 重连用「**指数退避 + 随机抖动**」——指数拉大间隔止损，抖动打散重连时刻，防止服务端重启时万级客户端**同步洪峰**（惊群）把它再压垮；成功后重试计数清零，下次故障从头起步。

---

## 一、为什么是「指数 + 抖动」

服务端重启/抖动时，如果所有客户端用固定间隔重连，会在同一瞬间**同时打进来**（惊群效应），把刚活过来的服务再打垮。两件事拆开：

- **指数退避**：间隔按 `1s → 2s → 4s → 8s…` 拉大，给服务端恢复时间；
- **随机抖动**：给间隔乘一个 `[0.5, 1)` 的随机系数，把「同一批客户端」的重连时刻**打散**，避免仍然同步。

```typescript
function backoff(attempt: number, base = 1000, max = 30000) {
  const exp = Math.min(base * 2 ** attempt, max); // 1s,2s,4s,8s... 封顶 30s
  return exp * (0.5 + Math.random() * 0.5);        // 全抖动：取 [50%,100%) 随机
}
```

## 二、生产级重连管理器

```typescript
class ReconnectableSocket {
  private ws: WebSocket | null = null;
  private attempt = 0;
  private retryTimer = 0;
  private heartbeat: Heartbeat | null = null;

  constructor(private url: string, private onMessage: (ev: MessageEvent) => void) {
    // ① 网络恢复：立刻重试，不等退避计时器
    window.addEventListener('online', () => this.schedule(0));
    // ② 页面隐藏：挂机大屏切后台不再白耗连接
    document.addEventListener('visibilitychange', () => {
      if (document.hidden) this.ws?.close();
      else this.schedule(0);
    });
  }

  connect() {
    this.ws = new WebSocket(this.url);

    this.ws.onopen = () => {
      this.attempt = 0; // 成功即清零，下次断线从头退避
      this.heartbeat = new Heartbeat(
        () => this.send({ type: 'ping' }),
        () => this.ws?.close(), // 判死 → close 触发 onclose 统一走重连
      );
      this.heartbeat.start();
      this.onOpen?.();
    };

    this.ws.onmessage = (ev) => {
      this.heartbeat?.feedPong();
      const msg = JSON.parse(ev.data);
      if (msg.type === 'pong') return;
      this.onMessage(msg);
    };

    this.ws.onclose = () => {
      this.heartbeat?.stop();
      this.heartbeat = null;
      this.schedule(this.attempt + 1);
    };
    // onerror 不单独处理：error 后必触发 close，统一从 close 走重连，避免双路径
  }

  private schedule(attempt: number) {
    clearTimeout(this.retryTimer);
    this.attempt = attempt;
    this.retryTimer = window.setTimeout(() => this.connect(), backoff(attempt));
  }

  send(data: unknown) { this.ws?.send(JSON.stringify(data)); }
  onOpen?: () => void; // 重连成功后由订阅层重放订阅
}
```

**三个加分细节**：

1. `onerror` 不单独写重连——error 之后必触发 `close`，单一入口防重复重连；
2. 监听 `window online`，网络恢复瞬间立即重试（用户感知最快）；
3. 成功后 `attempt = 0`，保证每次新故障都从 1s 起步。

## 面试回答

> 重连退避用指数 + 抖动。指数是把间隔 1s、2s、4s 翻倍封顶，给服务端恢复时间；抖动是给间隔乘随机系数，把重连时刻打散，否则服务端一重启，万级客户端固定间隔重连会同步惊群把它再压垮。细节上：onerror 不单独处理，error 必触发 close，统一从 close 走重连避免双路径；监听 online 事件网络恢复立即重试；成功后重试计数清零。
