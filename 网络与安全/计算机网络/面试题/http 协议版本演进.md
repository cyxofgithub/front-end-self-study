## HTTP 协议版本演进
| 版本      | 核心特性                                                         | 主要解决问题                     | 性能提升                       |
|----------|------------------------------------------------------------------|-------------------------------|-----------------------------|
| HTTP/1.0 | 无持久连接，短连接                                               | -                             | 基础传输能力                  |
| HTTP/1.1 | 持久连接 (Keep-Alive)、管道化、分块传输、缓存优化                  | 减少连接建立开销                | 页面加载约 2.8s               |
| HTTP/2   | 二进制分帧、多路复用、头部压缩 (HPACK)、服务器推送                | 解决 HTTP/1.1 队头阻塞         | 加载时间降至 1.8s，丢包恢复 300ms |
| HTTP/3   | 基于 QUIC（UDP）、0-RTT 连接、连接迁移、改进拥塞控制              | 解决 TCP 队头阻塞、提升连接迁移 | 加载时间 1.2s，丢包恢复 50ms   |

高频子问题：

**HTTP/2 多路复用如何解决队头阻塞？**
- HTTP/1.1 为了并发处理多个请求，要么开启多个 TCP 连接，要么用管线化（串行发送请求），但都存在队头阻塞（后续的请求需要等前面的请求传输结束）或连接开销大的问题。
- HTTP/2 只需要一个 TCP 连接，就可以同时传输多个请求 - 响应对应的帧。比如客户端同时发起请求 A 和请求 B，服务器会把 A 的响应拆成帧 A1、A2、A3，把 B 的响应拆成帧 B1、B2，然后在同一个 TCP 连接上交替发送这些帧（顺序可能是 A1→B1→A2→B2→A3），实现真正的并行传输。

**HTTP/3 为何选择 QUIC 而非 TCP？**
- 彻底解决tcp队头阻塞问题，虽然http2解决了http层面的队头阻塞问题，但是底层 tcp 在丢包时还是会阻塞后续的包体发送

| 特性           | TCP + TLS + HTTP/2         | QUIC (HTTP/3)                  | 优势说明                                 |
|---------------|----------------------------|-------------------------------|----------------------------------------|
| 队头阻塞       | 连接级阻塞                  | 流级独立，无阻塞               | **一个流丢包不影响其他流**                 |
| 连接建立延迟   | 3-RTT（首次）               | 1-RTT（首次）/ 0-RTT（复用）   | 减少 66% 握手延迟                       |
| 加密能力       | 依赖 TLS 扩展               | 内置 TLS 1.3（强制）           | 安全无额外成本，防中间人攻击            |
| 连接迁移       | 需重建连接                  | 无缝迁移（连接 ID 标识）        | 移动场景体验大幅提升                    |
| 部署灵活性     | 内核态，更新困难             | 用户空间，快速迭代              | 新特性快速普及，优化周期缩短             |
| 流控制粒度     | 连接级                      | 流级独立控制                    | 带宽分配更精准，资源利用率更高           |
