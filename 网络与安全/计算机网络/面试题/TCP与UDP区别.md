## TCP 与 UDP 区别

一句话结论：TCP 是**可靠、面向连接、按序交付**的传输协议，UDP 是**不可靠、无连接、尽力而为**的传输协议，选择取决于场景是追求可靠性还是低延迟。

### 核心对比表

| 维度 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接（三次握手） | 无连接，直接发送 |
| 可靠性 | 可靠，保证送达 | 不可靠，不保证送达 |
| 有序性 | 按序交付 | 不保证顺序 |
| 头部开销 | 20~60 字节 | 8 字节 |
| 传输效率 | 较低（有握手、确认、重传开销） | 高，直接发送 |
| 流量/拥塞控制 | 有（滑动窗口、慢启动等） | 无，应用层自行控制 |
| 适用场景 | HTTP、文件传输、邮件、数据库 | DNS、音视频直播、在线游戏、IoT |
| 双工模式 | 全双工 | 全双工 |

### 场景选择速记

| 场景 | 选 TCP | 选 UDP |
|------|--------|--------|
| 网页加载 | ✅ | |
| 大文件下载 | ✅ | |
| 视频直播 | | ✅（丢几帧不影响体验） |
| 视频电话 / VoIP | | ✅（低延迟优先于完整性） |
| 在线游戏 | | ✅（实时操作，丢包可插值） |

| 邮件 / 数据库 | ✅ | |

### 为什么 QUIC（HTTP/3）选择了 UDP 而不是 TCP？

这正是因为 TCP 和 UDP 的核心差异：

- **TCP 队头阻塞无法绕过**：TCP 是内核实现的，更新困难，且按序交付的特性导致一个包丢失就会阻塞后续所有数据。HTTP/2 虽然解决了 HTTP 层面的队头阻塞，但底层 TCP 的队头阻塞依然在。
- **UDP 足够轻量**：UDP 只提供端口和校验和，不保证任何东西，QUIC 在用户空间用 UDP 作为"底层通道"，把可靠性、拥塞控制、加密全部实现在 QUIC 协议层面，绕过了 TCP 内核实现的限制和队头阻塞特性。

简单记：**TCP 是内核里的"全包物业"，UDP 只是一个"邮政地址"，QUIC 用 UDP 这个地址自建了一套更先进的物流系统。**

### 面试口述版

> TCP 和 UDP 是传输层的两种协议，核心区别在于三个词：**连接、可靠、有序**。TCP 面向连接，通过三次握手建立连接，保证数据可靠到达且按序交付，代价是开销大、有队头阻塞。UDP 无连接，直接发包，不保证可靠和顺序，好处是头部只有 8 字节、无握手延迟、无队头阻塞。选 TCP 的场景是网页、文件传输这类需要完整性的，选 UDP 是视频、游戏、DNS 这类需要低延迟能容忍丢包的。HTTP/3 选 UDP 正是因为要绕开 TCP 的队头阻塞和内核态更新难的问题，在用户空间用 QUIC 自己实现可靠传输。
