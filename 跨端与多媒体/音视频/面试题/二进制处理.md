### 各二进制类型的具体业务使用场景（附选型建议）

| 类型           | 具体业务场景                                                                                                                                                                                                                     | 选型原因 & 实操要点                                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| ArrayBuffer    | 1. 解析音视频裸数据（如 WebAudio API 处理音频采样）<br>2. 解析自定义二进制协议（如物联网设备通信）<br>3. 处理 Canvas 像素数据（getImageData 底层）<br>4. WebSocket 接收/发送原始二进制数据                                       | - 原因：需要直接操作字节级数据，无额外封装，性能最高<br>- 要点：必须配合 TypedArray/DataView 使用，避免直接操作 ArrayBuffer            |
| TypedArray     | 1. 处理 Canvas 像素（Uint8ClampedArray 存储 RGBA 数据）<br>2. 解析图片格式（如 PNG 头信息、JPEG 字节）<br>3. 数值计算（如 Float32Array 处理传感器数据）<br>4. WebGL 传递顶点/纹理数据                                            | - 原因：类型固定，操作简单，数组式语法易上手<br>- 要点：优先选对应类型（如 Uint8 处理字节，Float32 处理浮点数），避免类型转换损耗      |
| DataView       | 1. 解析跨平台二进制文件（如读取 C 语言生成的 struct 数据，需指定大小端）<br>2. 解析混合类型二进制协议（如前 4 字节是 Int32，后 8 字节是 Float64）<br>3. 读取二进制文件的特定偏移数据                                             | - 原因：支持灵活指定数据类型和字节序，适配不同平台/协议<br>- 要点：明确字节序（littleEndian 参数），避免跨平台解析错误                 |
| Blob           | 1. 前端生成文件并下载（如 JSON 导出为 .json 文件、表格导出为 .csv）<br>2. 图片/视频预览（URL.createObjectURL 生成临时链接）<br>3. 大文件分片上传（slice 切割后分段发送）<br>4. Fetch/AXIOS 接收二进制响应（如下载文件）          | - 原因：带 MIME 类型，适配浏览器文件体系，支持分片<br>- 要点：生成的 blob URL 需手动 revoke 避免内存泄漏；分片时注意起始/结束偏移      |
| File           | 1. 表单文件上传（<input type="file"> 读取用户选择的图片/文档）<br>2. 拖放文件处理（ondrop 事件中获取 DataTransfer.files）<br>3. 读取文件元信息（如校验上传文件的后缀/大小/修改时间）                                             | - 原因：天然封装用户文件的元信息，兼容表单/拖放等交互<br>- 要点：通过 files[0] 获取单个文件，通过 FileList 遍历多个文件                |
| Base64         | 1. 小图片嵌入 HTML/CSS（如 icon 转 Base64 避免额外请求）<br>2. 接口传输二进制数据（如小程序/后端接口不支持二进制流时）<br>3. 本地存储二进制数据（如 localStorage 存图片片段）<br>4. 生成图片预览（canvas toDataURL 输出 Base64） | - 原因：文本格式，可嵌入/传输/存储，无需处理二进制流<br>- 要点：大文件避免用（体积增大 33%）；注意编码格式（如 UTF-8 转义）            |
| ReadableStream | 1. 大文件上传（流式分段上传，避免一次性加载 1GB+ 文件到内存）<br>2. 大文件下载（流式接收，边下载边写入本地）<br>3. 实时解析流式数据（如后端推送的 CSV 流、JSON 流）<br>4. WebSocket 流式接收二进制数据                           | - 原因：低内存占用，支持中断/暂停，适配大文件/实时数据<br>- 要点：通过 getReader() 消费流，处理完需释放；结合 async/await 简化异步逻辑 |

我特别理解你现在的感受——这些二进制相关的概念确实容易混淆，尤其是刚接触的时候，会分不清什么时候该用哪个。我换个更通俗的方式，用「生活类比+核心决策树」帮你理清，看完就能快速判断该用哪种方式。

### 辅助理解：生活化类比

把二进制数据想象成「水」，这些对象就是处理水的不同工具：

| 类型           | 生活化类比                                  | 一句话大白话解释                                        |
| -------------- | ------------------------------------------- | ------------------------------------------------------- |
| ArrayBuffer    | 一个固定容量的空水桶                        | 只装水（二进制），但没有勺子，没法直接喝/倒             |
| TypedArray     | 带刻度的勺子（只能舀固定量的水）            | 用固定规格的勺子去桶里舀水（操作固定类型字节）          |
| DataView       | 多功能量杯（可舀不同量的水，还能选大小勺）  | 灵活舀水，想舀多少舀多少，还能选字节序（大小端）        |
| Blob           | 贴了标签的密封水桶（标了「饮用水/矿泉水」） | 装水+标类型，方便运输/存放，还能把桶切开分着装          |
| File           | 超市买的瓶装水（有品牌/生产日期/容量）      | 密封水桶的升级版，多了文件名、修改时间等「商品信息」    |
| Base64         | 把水装到一个个小胶囊里（方便邮寄）          | 把二进制转成文本格式，方便在网络/文本里传输             |
| ReadableStream | 自来水龙头（水慢慢流，不用一次性接满桶）    | 一点点读取/处理数据，适合超大文件（避免一次性占满内存） |

#### 核心决策树（遇到需求，3 步选对工具）

不用死记硬背，按这个流程走，就能快速选对：

##### 第一步：先判断「数据来源」

-   如果是**用户上传的文件/拖放的文件** → 先拿到 `File`（它天生是 Blob，后续可转其他）
-   如果是**前端生成的二进制（如 JSON、Canvas 像素）** → 先搞成 `Blob` 或 `ArrayBuffer`
-   如果是**后端/网络传过来的原始二进制** → 先拿到 `ArrayBuffer`
-   如果是**要把二进制转文本传输/存储** → 用 `Base64`
-   如果是**处理超大文件（GB 级）** → 直接上 `ReadableStream`

##### 第二步：再判断「要做什么操作」

-   只是**上传/下载/预览文件** → 用 `Blob/File` 就够了（不用碰 ArrayBuffer）
-   需要**精准改某个字节/解析协议/处理像素** → 用 `ArrayBuffer + TypedArray/DataView`
-   需要**跨平台解析二进制（如和 C++/Java 交互）** → 用 `DataView`（指定字节序）
-   需要**文本化二进制（如存 localStorage/嵌 HTML）** → 用 `Base64`

##### 第三步：最后判断「数据大小」

-   小文件（<10MB）→ 随便用（Blob/Base64/ArrayBuffer 都可以）
-   大文件（>100MB）→ 用 `Blob.slice()` 分片 或 `ReadableStream` 流式处理（避免卡死）

### 高频场景选型示例（避坑指南）

#### 场景 1：用户上传 500MB 视频文件，需要分片上传

-   **选型**：File → Blob.slice() → ArrayBuffer → 接口上传
-   **实操步骤**：

    ```javascript
    async function uploadLargeFile(file) {
        const chunkSize = 10 * 1024 * 1024; // 10MB/片
        const totalChunks = Math.ceil(file.size / chunkSize);

        for (let i = 0; i < totalChunks; i++) {
            // 1. 切割 File（继承 Blob 的 slice 方法）
            const start = i * chunkSize;
            const end = Math.min(start + chunkSize, file.size);
            const chunk = file.slice(start, end);

            // 2. 转 ArrayBuffer（便于接口传输原始字节）
            const buffer = await new Response(chunk).arrayBuffer();

            // 3. 上传分片（携带分片索引、总数、文件 ID 等）
            await fetch('/api/upload-chunk', {
                method: 'POST',
                body: buffer,
                headers: {
                    'Content-Type': 'application/octet-stream',
                    'Chunk-Index': i,
                    'Total-Chunks': totalChunks,
                    'File-Name': file.name,
                },
            });
            console.log(`分片 ${i + 1}/${totalChunks} 上传完成`);
        }
        // 4. 通知后端合并分片
        await fetch('/api/merge-chunks', {
            method: 'POST',
            body: JSON.stringify({ fileName: file.name, totalChunks }),
        });
    }
    ```

#### 场景 2：前端生成并下载 JSON 配置文件

-   **选型**：JSON 字符串 → Blob → URL.createObjectURL → 下载
-   **实操步骤**：

    ```javascript
    function downloadJSONFile(data, fileName) {
        // 1. 转字符串，再封装为 Blob（指定 MIME 类型）
        const jsonStr = JSON.stringify(data, null, 2);
        const blob = new Blob([jsonStr], { type: 'application/json' });

        // 2. 生成临时 URL，创建下载链接
        const url = URL.createObjectURL(blob);
        const a = document.createElement('a');
        a.href = url;
        a.download = fileName || 'config.json'; // 强制指定文件名
        a.click();

        // 3. 释放资源
        URL.revokeObjectURL(url);
    }

    // 使用示例：下载用户配置
    downloadJSONFile({ theme: 'dark', fontSize: 16 }, 'user-config.json');
    ```

#### 场景 3：解析后端返回的二进制图片并预览

-   **选型**：Fetch 接收 ArrayBuffer → Blob → 预览 URL
-   **实操步骤**：

    ```javascript
    async function previewBinaryImage() {
        // 1. 请求二进制图片（responseType 设为 arraybuffer）
        const response = await fetch('/api/get-image');
        const buffer = await response.arrayBuffer();

        // 2. 转 Blob 生成预览 URL
        const blob = new Blob([buffer], { type: 'image/png' });
        const previewUrl = URL.createObjectURL(blob);

        // 3. 插入到页面预览
        const img = document.createElement('img');
        img.src = previewUrl;
        img.alt = '预览图';
        document.body.appendChild(img);

        // 4. 页面卸载时释放 URL
        window.addEventListener('unload', () => {
            URL.revokeObjectURL(previewUrl);
        });
    }
    ```

### 总结

1. **小文件/简单操作**：优先用 `Blob/File`（如普通文件上传/下载），无需接触底层 ArrayBuffer；
2. **精细字节操作**：用 `ArrayBuffer + TypedArray/DataView`（如解析协议、处理像素）；
3. **文本化传输/存储**：用 `Base64`（仅限小数据，如小图片、配置）；
4. **大文件/实时数据**：用 `ReadableStream`（流式处理，低内存）；
5. **跨平台/混合类型数据**：用 `DataView`（指定字节序，避免解析错误）。

核心选型原则：**优先使用上层封装（Blob/File），仅在需要精细控制时下沉到 ArrayBuffer 层级**，减少不必要的复杂度。
