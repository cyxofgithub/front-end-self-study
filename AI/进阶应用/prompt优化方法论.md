# Prompt 优化方法论

介绍行业通用的结构化方法论框架（如 STAR 法则），并展示如何将这些框架应用到 prompt 优化中。

## 1. STAR 法则

**定义**：Situation（情境）、Task（任务）、Action（行动）、Result（结果），用于结构化描述经历或解决问题。

### 在 Prompt 中的应用

**❌ 优化前：**

```
帮我优化一个登录功能
```

**✅ 优化后（使用 STAR 框架）：**

```
请按照 STAR 法则分析并优化登录功能：

**Situation（情境）：**
- 当前项目是一个电商平台
- 用户反馈登录流程复杂，流失率高
- 现有登录功能仅支持账号密码方式

**Task（任务）：**
- 优化登录体验，降低用户流失
- 支持多种登录方式（手机号、邮箱、第三方登录）
- 提升安全性

**Action（行动）：**
请提供：
1. 登录流程优化方案
2. 多种登录方式的实现方案
3. 安全措施建议（验证码、防暴力破解等）
4. 前端 UI/UX 改进建议

**Result（结果）：**
请评估优化后的预期效果：
- 用户体验提升指标
- 安全性提升措施
- 开发成本估算
```

**要点**：用 STAR 框架组织需求，让模型全面理解背景、任务、方案和预期结果

## 2. 5W1H 法则

**定义**：Who（谁）、What（什么）、When（何时）、Where（哪里）、Why（为什么）、How（如何），用于全面分析问题。

### 在 Prompt 中的应用

**❌ 优化前：**

```
写一个用户管理系统
```

**✅ 优化后（使用 5W1H 框架）：**

```
请设计一个用户管理系统，请按照 5W1H 框架分析需求：

**Who（谁）：**
- 目标用户：系统管理员、普通用户
- 开发团队：3 名前端、2 名后端

**What（什么）：**
- 功能：用户注册、登录、信息管理、权限控制
- 技术栈：Vue 3 + Node.js + MySQL

**When（何时）：**
- 开发周期：2 周
- 上线时间：下个月初

**Where（哪里）：**
- 部署环境：Linux 服务器
- 访问方式：Web 浏览器

**Why（为什么）：**
- 业务目标：统一管理平台用户，提升运营效率
- 技术目标：建立可扩展的用户体系

**How（如何）：**
请提供：
1. 系统架构设计
2. 数据库表结构设计
3. API 接口设计
4. 前端页面原型
5. 开发时间规划
```

**要点**：用 5W1H 确保需求完整，避免遗漏关键信息

## 3. PREP 法则

**定义**：Point（观点）、Reason（理由）、Example（例子）、Point（重申观点），用于清晰表达观点。

### 在 Prompt 中的应用

**❌ 优化前：**

```
解释一下为什么 React 比 Vue 好
```

**✅ 优化后（使用 PREP 框架）：**

```
请按照 PREP 法则分析 React 和 Vue 的优劣：

**Point（观点）：**
请客观分析 React 和 Vue 的各自优势，不要偏向任何一方

**Reason（理由）：**
请从以下维度分析：
1. 生态系统和社区支持
2. 学习曲线和开发效率
3. 性能和渲染机制
4. 企业采用率和就业市场
5. 适用场景

**Example（例子）：**
请为每个理由提供：
- 具体的技术对比示例
- 实际项目案例
- 代码示例对比

**Point（重申观点）：**
最后总结：
- 什么场景适合选择 React
- 什么场景适合选择 Vue
- 给出选择建议
```

**要点**：用 PREP 结构让模型提供有逻辑、有依据的分析

## 4. SCQA 框架

**定义**：Situation（情境）、Complication（冲突）、Question（问题）、Answer（答案），用于问题分析和解决方案。

### 在 Prompt 中的应用

**❌ 优化前：**

```
网站加载很慢，怎么办？
```

**✅ 优化后（使用 SCQA 框架）：**

```
请按照 SCQA 框架分析网站性能问题：

**Situation（情境）：**
- 网站类型：电商平台
- 当前状态：首页加载时间 5 秒，用户流失率高
- 技术栈：Vue 2 + Webpack 4

**Complication（冲突）：**
- 问题：首屏加载慢，影响用户体验和转化率
- 限制：不能大幅改动现有架构
- 挑战：需要在有限时间内快速见效

**Question（问题）：**
请分析：
1. 导致加载慢的主要原因是什么？
2. 哪些优化措施可以快速实施？
3. 如何平衡优化效果和开发成本？

**Answer（答案）：**
请提供：
1. 性能问题诊断报告
2. 优化方案（按优先级排序）
3. 具体实施步骤
4. 预期效果和评估指标
```

**要点**：用 SCQA 框架系统化分析问题，从情境到解决方案

## 5. AIDA 模型

**定义**：Attention（注意）、Interest（兴趣）、Desire（欲望）、Action（行动），用于营销和说服。

### 在 Prompt 中的应用

**❌ 优化前：**

```
写一个产品介绍
```

**✅ 优化后（使用 AIDA 框架）：**

```
请按照 AIDA 模型撰写产品介绍文案：

**产品信息：**
- 产品名：智能健身手环
- 核心功能：心率监测、运动记录、睡眠分析

**Attention（注意）：**
- 开头要吸引眼球，突出产品独特卖点
- 使用有力的标题或开场白

**Interest（兴趣）：**
- 详细介绍产品功能和优势
- 用具体数据说明产品价值

**Desire（欲望）：**
- 描述使用场景和带来的好处
- 激发用户的购买欲望

**Action（行动）：**
- 明确的行动号召
- 优惠信息或限时活动

请按照以上结构撰写，每部分控制在 50-100 字。
```

**要点**：用 AIDA 模型引导模型生成有说服力的营销文案

## 6. PDCA 循环

**定义**：Plan（计划）、Do（执行）、Check（检查）、Act（改进），用于持续改进。

### 在 Prompt 中的应用

**❌ 优化前：**

```
优化代码质量
```

**✅ 优化后（使用 PDCA 框架）：**

```
请按照 PDCA 循环优化代码质量：

**Plan（计划）：**
请分析当前代码库，制定优化计划：
1. 识别代码质量问题（代码重复、命名不规范、缺少注释等）
2. 设定优化目标（代码覆盖率、可维护性评分等）
3. 制定优化方案和优先级

**Do（执行）：**
请提供：
1. 具体的重构代码示例
2. 代码规范建议
3. 工具配置方案（ESLint、Prettier 等）

**Check（检查）：**
请说明：
1. 如何验证优化效果
2. 需要关注的指标
3. 检查清单

**Act（改进）：**
请提供：
1. 持续改进的建议
2. 团队协作规范
3. 代码审查流程
```

**要点**：用 PDCA 框架引导模型提供系统化的改进方案

## 7. MECE 原则

**定义**：Mutually Exclusive, Collectively Exhaustive（相互独立，完全穷尽），用于分类和分析。

### 在 Prompt 中的应用

**❌ 优化前：**

```
分析前端性能优化方法
```

**✅ 优化后（使用 MECE 原则）：**

```
请按照 MECE 原则分析前端性能优化方法：

**要求：**
1. 分类要相互独立（Mutually Exclusive）：每个优化方法只属于一个类别
2. 分类要完全穷尽（Collectively Exhaustive）：覆盖所有主要的优化方向

**请将优化方法分为以下类别：**
- 资源加载优化（图片、CSS、JS）
- 代码层面优化（算法、数据结构）
- 网络层面优化（CDN、HTTP/2、缓存）
- 渲染层面优化（DOM、重排重绘）
- 其他优化（Service Worker、预加载等）

每个类别请提供：
1. 具体优化方法
2. 实施难度和效果评估
3. 代码示例或配置示例
```

**要点**：用 MECE 原则确保分析全面且不重复

## 8. SMART 原则

**定义**：Specific（具体）、Measurable（可衡量）、Achievable（可达成）、Relevant（相关）、Time-bound（有时限），用于设定目标。

### 在 Prompt 中的应用

**❌ 优化前：**

```
制定一个学习计划
```

**✅ 优化后（使用 SMART 原则）：**

```
请按照 SMART 原则制定前端学习计划：

**背景：**
- 当前水平：初级前端（熟悉 HTML/CSS/JS 基础）
- 目标：3 个月内达到中级前端水平

**请为每个学习目标应用 SMART 原则：**

**Specific（具体）：**
- 明确要学习的具体技术（如 Vue 3、TypeScript、Webpack）

**Measurable（可衡量）：**
- 设定可量化的指标（如完成 3 个项目、掌握 20 个核心 API）

**Achievable（可达成）：**
- 确保目标在能力范围内，可以达成

**Relevant（相关）：**
- 学习内容要与职业目标相关

**Time-bound（有时限）：**
- 每个目标都要有明确的时间节点

请输出详细的学习计划表。
```

**要点**：用 SMART 原则确保目标清晰、可执行、可衡量

## 9. 金字塔原理

**定义**：结论先行，以上统下，归类分组，逻辑递进，用于结构化表达。

### 在 Prompt 中的应用

**❌ 优化前：**

```
分析一下这个项目的技术选型
```

**✅ 优化后（使用金字塔原理）：**

```
请按照金字塔原理分析项目技术选型：

**结论先行：**
请先给出技术选型的总体建议（推荐的技术栈组合）

**以上统下：**
然后按照以下结构展开：

**1. 前端框架选择**
   - 理由 1：生态和社区支持
   - 理由 2：开发效率
   - 理由 3：性能表现

**2. 后端框架选择**
   - 理由 1：...
   - 理由 2：...

**3. 数据库选择**
   - 理由 1：...
   - 理由 2：...

**归类分组：**
请将相关技术归类（如前端技术、后端技术、工具链）

**逻辑递进：**
请按照重要性或优先级排序，最重要的放在前面

**输出格式：**
```

## 技术选型建议

[总体结论]

### 1. [分类 1]

[理由和说明]

### 2. [分类 2]

[理由和说明]

```

```

**要点**：用金字塔原理让输出结构清晰，结论明确，逻辑严密

## 10. RACI 矩阵

**定义**：Responsible（负责）、Accountable（问责）、Consulted（咨询）、Informed（知情），用于明确角色和责任。

### 在 Prompt 中的应用

**❌ 优化前：**

```
规划一个项目开发流程
```

**✅ 优化后（使用 RACI 矩阵）：**

```
请按照 RACI 矩阵规划项目开发流程：

**项目角色：**
- 项目经理（PM）
- 前端开发（FE）
- 后端开发（BE）
- UI 设计师（UI）
- 测试工程师（QA）

**项目阶段：**
1. 需求分析
2. UI 设计
3. 前端开发
4. 后端开发
5. 联调测试
6. 上线部署

**请为每个阶段和角色分配 RACI：**
- R（Responsible）：具体执行者
- A（Accountable）：最终责任人
- C（Consulted）：需要咨询的人
- I（Informed）：需要知情的人

输出格式：
| 阶段 | PM | FE | BE | UI | QA |
|------|----|----|----|----|----|
| 需求分析 | A | R | C | C | I |
| ... | ... | ... | ... | ... | ... |
```

**要点**：用 RACI 矩阵明确各角色职责，避免责任不清

## 方法论选择指南

根据不同场景选择合适的方法论：

| 场景          | 推荐方法论 | 说明                                       |
| ------------- | ---------- | ------------------------------------------ |
| 描述经历/案例 | STAR 法则  | 结构化描述情境、任务、行动、结果           |
| 需求分析      | 5W1H       | 全面覆盖谁、什么、何时、哪里、为什么、如何 |
| 观点表达      | PREP 法则  | 观点-理由-例子-重申观点                    |
| 问题分析      | SCQA 框架  | 情境-冲突-问题-答案                        |
| 营销文案      | AIDA 模型  | 注意-兴趣-欲望-行动                        |
| 持续改进      | PDCA 循环  | 计划-执行-检查-改进                        |
| 分类分析      | MECE 原则  | 相互独立，完全穷尽                         |
| 目标设定      | SMART 原则 | 具体、可衡量、可达成、相关、有时限         |
| 结构化表达    | 金字塔原理 | 结论先行，逻辑递进                         |
| 责任分配      | RACI 矩阵  | 明确角色和责任                             |

## 总结

这些行业通用的方法论框架可以显著提升 prompt 的结构化和专业性：

1. **结构化思维**：用框架组织 prompt，让模型理解更清晰
2. **全面性**：确保不遗漏关键信息（如 5W1H、MECE）
3. **逻辑性**：按照框架的逻辑顺序组织内容（如 STAR、PREP）
4. **可执行性**：明确目标和行动（如 SMART、PDCA）

在实际使用中，可以根据具体场景选择合适的方法论，或者组合使用多个框架。
