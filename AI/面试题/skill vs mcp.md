## Skill、MCP区别

### 一句话总结

- **MCP（Model Context Protocol）**：是一种**通信协议**，定义模型如何与外部工具/资源交互，解决的是"模型怎么调用工具"的问题。
- **Skill（技能）**：是一种**可复用的工作流/提示词模板**，封装了完成特定任务所需的指令、工具和资源，解决的是"如何高质量完成某类任务"的问题。

### 核心区别

| 维度           | MCP                                                           | Skill                                                  |
| -------------- | ------------------------------------------------------------- | ------------------------------------------------------ |
| **定位**       | 协议/标准                                                     | 工作流/模板                                            |
| **层级**       | 基础设施层（传输层）                                          | 应用层（业务层）                                       |
| **作用**       | 定义模型与外部系统的通信规范（Tool/Resource/Prompt 三大原语） | 封装领域知识、操作步骤、工具组合，形成可复用的任务单元 |
| **类比**       | 类似 HTTP 协议——定义请求/响应格式                             | 类似一个 NPM 包——封装了特定功能的完整实现              |
| **关注点**     | "能否连通"——标准化接口、数据传输格式、权限控制                | "做得好不好"——任务分解、上下文组织、最佳实践内化       |
| **开发者视角** | 实现一个 MCP Server，暴露 Tool/Resource/Prompt                | 编写一个 SKILL.md，声明元数据 + 核心指令 + 所需工具    |

### 关系：互补而非替代

- **Skill 依赖 MCP**：Skill 中声明的工具，底层可以通过 MCP Server 提供。例如 Skill 里写"调用 `get_design_context` 获取 Figma 设计"，这个工具就是通过 Figma MCP Server 暴露的。
- **MCP 提供能力，Skill 提供用法**：MCP 让模型"有能力"调用外部工具，Skill 告诉模型"什么时候、按什么步骤"去调用这些工具。
- **一句话**：MCP 是水管，Skill 是菜谱。水管负责把原料（数据/工具）送进来，菜谱决定怎么把原料做成菜。

### 具体示例

以"根据 Figma 设计稿生成前端代码"为例：

- **MCP 层面**：Figma MCP Server 提供了 `get_design_context`、`get_screenshot`、`get_code_for_selection` 等 Tool，以及设计稿文件的 Resource 访问能力。
- **Skill 层面**：一个 `figma-to-code` Skill 会声明——"当用户给 Figma 链接时，先用 `get_design_context` 获取设计结构，再用 `get_screenshot` 确认视觉，然后按项目的技术栈规范（如 Tailwind CSS + Vue3）生成代码，最后检查响应式适配"。

MCP 让你能调 Figma API，Skill 让你知道调完 Figma API 之后该干什么。

### 延伸：Skill vs Rules

Skill 也常和 Rules 对比：

- **Rules**：静态规则集合，每次对话都生效（如"始终用 TypeScript"、"不要写注释"）。
- **Skills**：动态技能集合，按需语义匹配加载——用户说了相关任务才激活。
