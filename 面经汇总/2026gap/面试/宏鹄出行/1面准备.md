#### 说说 React 虚拟 DOM 和 Diff 算法的工作原理，React 16 之后的 Fiber 架构解决了什么问题？

- 虚拟 DOM：是对 DOM 的抽象描述，包含标签名、属性、子节点等信息。组件状态变化时，先生成新的虚拟 DOM ，再和旧树对比差异，最后只把变更部分更新到真实 DOM，减少频繁 DOM 操作的性能损耗。

- diff比对是先进行同层比对，如果类型和key相同则更新属性和内容，如果类型和key不同则创建新节点、删除旧节点；

- react16 渲染过程同步且不可中断会造成页面阻塞卡顿，引入fiber把渲染任务拆分成一个个小的 Fiber 单元，通过时间切片在浏览器空闲时执行，任务可中断、可恢复、可按优先级调度，保证页面交互流畅。

#### React Hooks 的实现原理？useState/useEffect/useMemo/useCallback 的作用与依赖数组逻辑？

- 实现原理：Hooks 基于 Fiber 节点的 memoizedState 链表存储状态，每个 Hook 对应链表中的一个节点。组件首次渲染时按调用顺序依次创建 Hook 节点并挂载到链表上，更新时按相同顺序读取对应节点的状态，这也是 Hooks 不能写在条件 / 循环里的原因。

- 核心 Hooks 作用：
    - useState：声明函数组件的状态，返回状态值和更新函数，更新会触发组件重渲染；
    - useEffect：处理副作用，如数据请求、事件绑定、DOM 操作，在组件渲染完成后异步执行；
    - useMemo：缓存计算结果，依赖不变时直接返回缓存值，避免每次渲染都执行高开销计算；
    - useCallback：缓存函数引用，依赖不变时保持函数引用一致，常配合 memo 避免子组件无效重渲染。

- 依赖数组逻辑：
    - React 对依赖项做浅比较，对比前后两次渲染的引用 / 值是否变化。空数组 [] 表示只在组件挂载时执行一次；不传依赖数组表示每次渲染后都会执行。常见坑是闭包陷阱：副作用里捕获的是当前渲染周期的状态值。
