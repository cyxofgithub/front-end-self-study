## 能够熟练运用 JS/AJAX/HTML5/CSS/AS 等前端开发技术构建高性能 Web 应用程序

### AS

#### [什么是 AssemblyScript？它和 TypeScript、JavaScript 有什么核心区别？](../../../../性能与浏览器/WebAssembly/03_AssemblyScript面试题.md#1-assemblyscript-是什么和-typescriptjavascript-有什么区别)

AssemblyScript 是语法接近 TypeScript、但直接编译到 Wasm 的静态类型语言，不是能运行任意 TS/JS 的编译器。

#### [为什么选择用 AssemblyScript 开发 WebAssembly？相比其他 Wasm 开发方案有什么优势？](../../../../性能与浏览器/WebAssembly/03_AssemblyScript面试题.md#2-为什么选-assemblyscript-开发-wasm)

AS 的优势是 TS 团队学习和迁移成本低，适合独立计算内核；复用原生库选 C/C++，复杂长期核心库常优先评估 Rust。

#### [JS 和 Wasm 之间怎么传递数据？有哪些数据类型限制？数据传参会带来什么性能损耗？](../../../../性能与浏览器/WebAssembly/03_AssemblyScript面试题.md#3-js-和-wasm-怎么传数据)

单个数值（如 `i32/f64`）可直接传递；它们也叫标量，即一个值，不是数组或对象。字符串、数组和对象通常要先写入线性内存，再传指针和长度；损耗主要来自跨边界调用、分配、拷贝和编解码，所以 API 应该批量化。

#### [AssemblyScript 的内存管理机制是怎样的？和 JS 的垃圾回收有什么不同？](../../../../性能与浏览器/WebAssembly/03_AssemblyScript面试题.md#4-assemblyscript-怎么管理内存)

是，默认情况下两者都会自动回收对象。JS GC 管理 JS 引擎堆；AS 运行时的 GC 管理 Wasm 线性内存中的 AS 对象，两套 GC 相互独立。Wasm 本身不会自动回收线性内存；JS 长期持有 AS 指针时还要正确 `pin/unpin`。

#### [什么业务场景适合用 Wasm 做性能优化？飞书文档里哪些能力适合用 AS 重构？](../../../../性能与浏览器/WebAssembly/03_AssemblyScript面试题.md#5-什么业务适合-wasm飞书文档哪些能力可候选)

适合 CPU 密集、数据可批处理、不依赖 DOM 的热点；文档中可评估导入导出解析、CRDT 编解码/合并、索引、diff、表格公式和媒体处理。

#### [怎么调试和 profiling AssemblyScript 代码？怎么评估它的性能收益？](../../../../性能与浏览器/WebAssembly/03_AssemblyScript面试题.md#6-怎么调试profiling-和评估收益)

用 source map/`.wat`/DevTools 定位，基准要比较 release 构建的端到端 p50/p95/p99，并统计初始化、胶水拷贝、内存、包体和正确性。
