# Vite 的 HMR 和 Webpack 的 HMR 的本质区别

## 核心区别

### Webpack HMR

-   **构建方式**：先打包构建整个应用，生成 bundle
-   **更新流程**：文件变化 → 重新编译相关模块 → 通过 WebSocket 推送更新 → 浏览器替换模块
-   **编译时机**：启动时全量编译，文件变化时增量编译

### Vite HMR

-   **构建方式**：基于原生 ESM，无需打包，浏览器直接请求模块
-   **更新流程**：文件变化 → 只编译改动的单个文件 → 通过 WebSocket 通知 → 浏览器重新请求该模块
-   **编译时机**：按需编译，只编译被请求的文件

## 为什么 Vite 的 HMR 更快？

### 1. **无需打包**

-   **Webpack**：需要先构建依赖图，打包成 bundle，即使只改一个文件也可能影响整个 chunk
-   **Vite**：利用浏览器原生 ESM，直接按需加载，无需预先打包

### 2. **按需编译**

-   **Webpack**：文件变化时需要重新编译相关模块，可能涉及整个依赖链
-   **Vite**：只编译改动的单个文件，其他模块保持不变

### 3. **更精确的更新范围**

-   **Webpack**：基于 chunk 的更新，可能更新整个 chunk 内的所有模块
-   **Vite**：基于单个模块的更新，只更新实际变化的文件

### 4. **编译工具性能**

-   **Webpack**：使用 Babel/TypeScript 等较慢的编译器
-   **Vite**：开发环境使用 esbuild（Go 语言编写），编译速度更快

## 工作原理对比

### Webpack HMR 流程

```
文件变化 → 重新编译模块 → 生成更新补丁 → WebSocket 推送 → 浏览器应用更新
```

### Vite HMR 流程

```
文件变化 → 编译单个文件 → WebSocket 通知文件路径 → 浏览器重新请求该模块
```

## 总结

**本质区别**：Webpack 是**打包后更新**，Vite 是**按需编译更新**

**性能优势**：Vite 通过利用浏览器原生 ESM 和按需编译，避免了不必要的打包和编译过程，因此 HMR 速度更快。
