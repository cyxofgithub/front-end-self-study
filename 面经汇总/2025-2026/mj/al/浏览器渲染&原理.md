## 浏览器渲染&原理

核心流程可以分为 6 步，整体是从代码到屏幕像素的转换过程：

1. 首先解析 HTML，生成 DOM 树，遇到 script 标签会暂停 HTML 解析，优先执行 JS；
2. 然后解析 CSS，生成 CSSOM 树，CSSOM 是阻塞渲染的，必须等它构建完成才能往下走；
3. 接着结合 DOM 树和 CSSOM 树，生成只包含可见节点的渲染树，像 display: none 的节点会被排除；
4. 之后进行布局（也叫重排），计算每个节点的位置和尺寸，生成布局树；
5. 再执行绘制（也叫重绘），给每个节点填充颜色、阴影等视觉样式；
6. 最后是合成，浏览器把绘制好的图层合并，通过 GPU 渲染到屏幕上。

**重排一定会触发重绘，但重绘不一定触发重排。优化的核心思路就是减少重排重绘，比如用 transform 做动画，它只会触发合成，性能最高**

### 可能拓展：

#### 优化手段

1. 批量修改 DOM，比如用 DocumentFragment；
2. 避免频繁读取布局属性，一次性缓存；
3. 动画优先用 transform/opacity，只触发合成，不触发重排重绘；
4. 把频繁重排的元素设为 absolute/fixed，脱离文档流。

**为什么读取布局属性会触发重排**

“读取属性” 本身不会制造重排，读取属性时在异步渲染队列中存在布局任务，此时会强制清空渲染队列触发重排，以保证读取到最新属性

**为什么把频繁重排的元素设为 absolute/fixed，脱离文档流可以减少？**

-   浏览器会为 absolute/fixed 元素创建**独立的渲染层（甚至合成层），这个渲染层的布局计算是独立的**
-   处于文档流中的元素，其位置、尺寸的变化会触发连锁反应：比如一个普通块级元素高度增加，下方所有元素的位置都会被推挤，浏览器需要重新计算这些元素的布局，导致大范围重排。
-   而 absolute/fixed 定位的元素完全脱离文档流，它的布局不再依赖父元素或相邻元素，也不会影响其他元素的位置和尺寸。即使这个元素频繁改变位置、尺寸，也只会触发自身的小范围重排，不会波及文档流中的其他元素。

##### script 标签 async 和 defer 属性区别：

    -   async：异步下载（不阻塞 HTML 解析），脚本下载完瞬间立即执行同时中断 html 解析，脚本加载顺序取决于加载速度与编写顺序无关
    -   defer：异步下载（不阻塞 HTML 解析），但下载完成后不会立即执行，而是等待整个 HTML 解析完毕（DOM 构建完成），再按照脚本在 HTML 中的书写顺序依次执行

为什么这么设计？async 可以用于不依赖 dom 的独立脚本尽快执行（广告、统计）、defer 用于依赖 dom 的脚本

##### （display: none） 和 （visibility: none） 区别：

-   display: none 的节点不会进入渲染树，而 visibility: hidden 的节点会进入，只是不显示，所以前者触发重排，后者只触发重绘
