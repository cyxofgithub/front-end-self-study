## sse 自定义有什么优势

| **对比维度**    | **原生 SSE**                                                                       | **自定义 SSE（扩展版）**                                                       |
| --------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 消息格式        | 仅支持 `data/event/id/retry` 4 个固定字段                                          | 可自定义扩展字段（`traceId/priority` 等），格式灵活                            |
| 消息确认（ack） | 无原生机制，**技术上可加 HTTP ack 接口，但无标准化逻辑**（需开发者手动写零散代码） | 无原生机制，**将 HTTP/WS ack + 消息重推 + 状态记录封装为标准化方案**，开箱即用 |
| 连接管理        | 仅支持 `retry` 字段配置重连间隔，无心跳/鉴权                                       | 封装自定义心跳（ping/pong）、鉴权、连接分组/清理逻辑                           |
| 传输效率优化    | 无内置方案，仅支持 JSON/文本                                                       | 集成压缩（gzip/protobuf）、分片/合并、按需传输逻辑                             |
| 错误处理        | 仅暴露通用错误，无业务级错误码                                                     | 自定义错误类型（`token_expired` 等）+ 错误上下文，配套处理逻辑                 |
| 方案复用性      | 无封装，每次使用需重复写基础逻辑                                                   | 封装为工具/库，支持多业务场景复用                                              |

## canvas 和 svg 渲染区别

### 核心差异

| 特性     | SVG                                                                  | Canvas                                                      |
| -------- | -------------------------------------------------------------------- | ----------------------------------------------------------- |
| 渲染模式 | 矢量图形（基于 XML 描述），声明式（描述 "画什么"），由浏览器解析渲染 | 位图（像素画布），命令式（描述 "怎么画"），由 JS 逐像素绘制 |
| 图形本质 | 可无限缩放不失真，每个图形都是 DOM 元素                              | 缩放会失真，整体是一个 DOM 元素，内部图形无独立 DOM         |
| 事件交互 | 每个图形元素可单独绑定事件（如点击某条路径）                         | 无独立元素事件，需手动计算点击坐标判断命中区域              |
| 更新方式 | 修改 DOM 属性即可实时更新，浏览器自动重绘                            | 需清空画布后重新绘制整个区域（局部更新需手动处理）          |
| 内存占用 | 元素越多（如大量节点），DOM 树越复杂，内存占用越高                   | 仅占用画布本身的内存，元素数量不影响内存（仅影响绘制性能）  |

### 使用场景

| 技术   | 适用场景                                                               | 不适用场景                                   |
| ------ | ---------------------------------------------------------------------- | -------------------------------------------- |
| SVG    | 图标、简单图表（如饼图）、静态矢量图形、需精准交互的图形（如地图标注） | 海量粒子动画、游戏、复杂像素处理             |
| Canvas | 数据可视化大屏（百万级数据）、游戏、粒子效果、视频处理、实时绘图       | 需精准交互的矢量图形、高频局部更新的简单图形 |

## 服务端渲染白屏时间怎么优化

# 服务端渲染（SSR）白屏时间优化方案总结表

| **优化维度**                     | **优化手段**      | **具体操作**                                                                               | **核心收益**                             |
| -------------------------------- | ----------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **服务端侧（核心耗时）**         | **数据请求优化**  | 1. 批量+并行请求<br>2. Redis/内存缓存高频数据<br>3. 首屏降级非核心数据                     | 减少数据等待时间，降低重复计算开销       |
|                                  | 组件渲染优化      | 1. 仅渲染首屏组件，其余客户端激活<br>2. 剔除首屏无关逻辑（埋点/统计）                      | 减少服务端 VDOM 生成和 HTML 拼接计算量   |
|                                  | 模板引擎优化      | 1. 预编译模板（如 Vue 模板预编译）<br>2. 模板复杂计算移到服务端预处理                      | 跳过运行时编译步骤，降低 CPU 消耗        |
|                                  | 服务性能调优      | 1. Node.js 开启集群模式<br>2. 优化 GC 避免内存泄漏<br>3. 使用高性能框架（Nest.js）         | 提升并发处理能力，减少 GC 停顿影响       |
| **网络传输侧（减少加载耗时）**   | **HTML 体积压缩** | 1. 开启 Gzip/Brotli 压缩<br>2. html-minifier 移除注释/空白<br>3. 内联首屏关键 CSS/JS       | 降低传输体积，减少额外请求次数           |
|                                  | CDN 加速分发      | 1. 静态/准静态页面缓存到 CDN 边缘节点<br>2. 动态页面使用边缘计算 SSR                       | 缩短用户与服务器的物理距离，降低传输延迟 |
|                                  | 协议与头信息优化  | 1. 启用 HTTP/2/HTTP/3 多路复用<br>2. 清理不必要响应头                                      | 提升传输效率，减少额外开销               |
| **客户端侧（提升解析渲染效率）** | **关键内容优先**  | 1. 首屏元素加`priority`属性<br>2. 非首屏资源`loading="lazy"`延迟加载                       | 优先展示核心内容，缩短首次内容绘制时间   |
|                                  | 客户端激活优化    | 1. `link rel="preload"`预加载客户端 JS<br>2. 选择性水合（只激活交互组件）                  | 避免 JS 加载阻塞，减少水合耗时           |
|                                  | **避免渲染阻塞**  | 1. 内联关键 CSS，消除 CSSOM 阻塞<br>2. 非核心 JS 用`defer`加载                             | 加快浏览器 DOM 解析和渲染速度            |
| **进阶优化方案**                 | 混合渲染模式      | 静态页面用 SSG，动态页面用 SSR，非首屏用 CSR                                               | 兼顾静态页面极速加载和动态页面灵活性     |
|                                  | 骨架屏兜底        | 服务端返回 HTML 时内联骨架屏结构                                                           | 视觉上消除白屏，提升用户体验             |
|                                  | 监控量化          | 跟踪 FCP（首次内容绘制）、TTFB（首字节时间）指标<br>用 Lighthouse/Chrome DevTools 定位瓶颈 | 验证优化效果，指导后续迭代               |

## 低代码

### 为什么要自研

1. 业务定制：样式定制，目前的开源低代码框架里这部分的支持其实很弱，比如像阿里的 lowcode-engine 还是百度的 amis 定位更倾向于json配置代码，所以对编辑器的支持也比较少
2. 交互比较生硬：特别是编辑区交互，其实比较难用
3. 性能问题：编辑端和渲染端耦合，编辑端需要拖拽、配置面板、选中的能力，渲染端其实只需要渲染能力
4. 维护问题：这些低代码框架其实挺重的，如果真出了问题能不能及时修复，如果要自己去啃源码成本也很高
