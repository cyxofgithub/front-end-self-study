### React Native 运行流程核心解析

RN 的核心特点是**跨平台**和**桥接机制**，它不像纯原生应用直接运行，也不像纯前端应用跑在浏览器里，而是结合了 JS 逻辑和原生渲染，整体运行流程可以分为 4 个核心阶段：

#### 1. 应用启动阶段

-   当你打开 RN 应用时，首先执行的是**原生端（iOS/Android）** 的启动代码：
    -   iOS：启动 `AppDelegate.m`，初始化 `RCTBridge`（RN 桥接核心）；
    -   Android：启动 `MainApplication.java`，初始化 `ReactInstanceManager`。
-   原生端会启动一个**JS 引擎**（默认是 Hermes，也可以用 JSC/V8），并加载应用的 JS 代码包（`index.js`/`App.js` 打包后的 bundle 文件）。
-   此时 JS 环境和原生环境完成初始化，两者通过 **Bridge（桥接层）** 建立通信通道。

#### 2. JS 逻辑执行阶段

-   JS 引擎执行你的 RN 业务代码（组件、状态、逻辑等），RN 会将 JSX 语法转换成 **React 虚拟 DOM（Virtual DOM）**，再进一步转换成 RN 特有的 **Shadow Tree（影子树）**（描述界面结构的纯数据结构）。
-   这个阶段完全在 JS 线程中执行，不会直接操作原生界面，保证了跨平台逻辑的统一性。

#### 3. 桥接通信与布局计算阶段

-   JS 线程将 Shadow Tree 通过 Bridge 传递给原生端的 **UI Manager**（UI 管理器）。
-   UI Manager 会调用原生的布局引擎（iOS 是 YogaKit，Android 是 Yoga），根据 Shadow Tree 计算每个组件的位置、大小（布局计算）。
-   计算完成后，UI Manager 会生成原生可识别的**渲染指令**。

#### 4. 原生渲染与交互阶段

-   原生主线程（UI 线程）接收渲染指令，创建对应的原生组件（比如 RN 的 `<View>` 对应 iOS 的 `UIView`、Android 的 `ViewGroup`，`<Text>` 对应 `UILabel`/`TextView`），并渲染到屏幕上。
-   当用户和界面交互（比如点击按钮）：
    -   原生端捕获事件，通过 Bridge 传递给 JS 线程；
    -   JS 线程处理事件逻辑（比如修改 `state`），生成新的 Shadow Tree；
    -   重复“桥接通信 → 布局计算 → 原生渲染”的流程，更新界面。

#### 补充：热更新/调试的特殊流程

-   开发阶段：RN 不会打包 JS 代码，而是通过 Metro 服务将 JS 代码实时传给原生端，修改代码后无需重新编译原生工程，直接刷新即可（热重载）；
-   生产阶段：JS 代码会被打包成 `bundle` 文件，和原生应用一起打包成安装包，运行时直接加载本地 `bundle`，也可通过热更新框架替换 `bundle` 实现无需应用商店审核的更新。

### 总结

1. RN 启动先跑原生代码，初始化 JS 引擎和桥接层，再加载执行 JS 逻辑；
2. JS 层只负责生成界面描述（Shadow Tree），通过桥接层传给原生端；
3. 原生端负责布局计算和最终的界面渲染，交互事件则反向通过桥接层传给 JS 处理。

这个“JS 逻辑 + 原生渲染”的分离模式，既保证了跨平台的开发效率，又能让界面拥有原生的性能和体验。
