## SSE 底层原理

跟 Websocket 一样都是基于 http，不同的是 websocket 只是利用 http 进行握手；而 SSE 还是利用 http1.1 的流式传输能力在这个基础上建立了自己的规范

### 建立请求头和响应头规范

#### 客户端请求头

客户端通过 `EventSource` API 发起请求时，浏览器会自动设置以下请求头：

```http
GET /events HTTP/1.1
Host: example.com
Accept: text/event-stream
Cache-Control: no-cache
```

**关键请求头：**

-   `Accept: text/event-stream`：告诉服务器客户端期望接收 SSE 格式的数据
-   `Cache-Control: no-cache`：禁用缓存，确保获取最新数据

**备注：** 如果想自定义请求不用 EventSource Api 可以自定义关键请求头发起

#### 服务器响应头

服务器必须设置以下响应头来建立 SSE 连接：

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
Access-Control-Allow-Origin: *
```

**关键响应头说明：**

-   `Content-Type: text/event-stream`：**必需**，标识响应为 SSE 格式
-   `Cache-Control: no-cache`：**必需**，防止代理服务器缓存响应
-   `Connection: keep-alive`：**推荐**，保持 HTTP 连接打开，实现长连接
-   `Access-Control-Allow-Origin: *`：**跨域时需要**，允许跨域访问
-   `X-Accel-Buffering: no`：**Nginx 代理时推荐**，禁用 Nginx 缓冲，确保实时推送

### 数据规范

SSE 使用纯文本格式传输数据，每条消息由多个字段组成，字段之间用换行符分隔，消息之间用**两个换行符**（`\n\n`）分隔。

#### 数据格式规范

```
field: value\n
field: value\n
\n
```

**支持的字段类型：**

1.  **`data:`** - 消息内容（必需）

    ```
    data: Hello World\n\n
    ```

    多行数据：

    ```
    data: First line\n
    data: Second line\n\n
    ```

2.  **`event:`** - 事件类型（可选）

    ```
    event: message\n
    data: Hello World\n\n
    ```

    客户端可以通过 `eventSource.addEventListener('message', handler)` 监听特定事件

3.  **`id:`** - 事件 ID（可选）

    ```
    id: 123\n
    data: Hello World\n\n
    ```

    用于断线重连时指定最后接收的事件 ID

4.  **`retry:`** - 重连间隔（可选，单位：毫秒）

    ```
    retry: 3000\n
    data: Hello World\n\n
    ```

    指定连接断开后重新连接的等待时间

5.  **注释行** - 以 `:` 开头
    ```
    : This is a comment\n
    data: Hello World\n\n
    ```
    注释行会被客户端忽略，可用于心跳检测

#### 完整示例

**服务器发送：**

```
: 心跳检测\n
event: userMessage\n
id: 1001\n
data: {\n
data:   "user": "Alice",\n
data:   "message": "Hello"\n
data: }\n\n

event: systemMessage\n
id: 1002\n
data: System is running\n\n

retry: 5000\n
data: Reconnection settings\n\n
```

**客户端接收：**

```javascript
const eventSource = new EventSource('/events');

// 监听默认 message 事件
eventSource.onmessage = (event) => {
    console.log('Data:', event.data);
    console.log('ID:', event.lastEventId);
};

// 监听自定义事件
eventSource.addEventListener('userMessage', (event) => {
    const data = JSON.parse(event.data);
    console.log('User:', data.user);
    console.log('Message:', data.message);
});

eventSource.addEventListener('systemMessage', (event) => {
    console.log('System:', event.data);
});
```

#### 数据格式要点

1.  **每条消息必须以两个换行符结尾**（`\n\n`），否则客户端不会解析
2.  **字段名不区分大小写**，但习惯使用小写
3.  **字段值中的换行符会被保留**，多行数据需要多个 `data:` 字段
4.  **`data:` 字段可以出现多次**，最终会被合并成一个字符串，用 `\n` 连接
5.  **如果只有 `data:` 字段，可以省略 `event:`**，默认为 `message` 事件
6.  **`id:` 字段会更新 `EventSource.lastEventId`**，用于断线重连

#### 心跳机制

为了防止连接超时，服务器可以定期发送注释行（心跳包）：

```
: heartbeat\n\n
```

客户端会忽略注释行，但可以保持连接活跃。

### 与 HTTP/1.1 流式传输的关系

SSE 基于 HTTP/1.1 的**分块传输编码**（Chunked Transfer Encoding）：

1.  服务器设置 `Transfer-Encoding: chunked`（通常由服务器自动处理）
2.  响应体可以分多次发送，每次发送一个数据块
3.  每个数据块包含长度和内容，最后以 `0\r\n\r\n` 结束
4.  SSE 在此基础上定义了数据格式规范（`data:`、`event:` 等字段）

### 连接生命周期

1.  **建立连接**：客户端发起 HTTP GET 请求，服务器返回 SSE 响应头
2.  **保持连接**：服务器持续发送数据，连接保持打开状态
3.  **断线重连**：连接断开后，客户端根据 `retry:` 字段自动重连
4.  **关闭连接**：客户端调用 `eventSource.close()` 或服务器关闭连接

### 与 WebSocket 的区别

| 特性       | SSE                     | WebSocket         |
| ---------- | ----------------------- | ----------------- |
| 协议       | HTTP/1.1                | 独立协议（ws://） |
| 通信方向   | 单向（服务器 → 客户端） | 双向              |
| 数据格式   | 文本（UTF-8）           | 文本或二进制      |
| 自动重连   | 支持                    | 需手动实现        |
| 浏览器支持 | 良好（除 IE）           | 良好              |
| 实现复杂度 | 简单                    | 相对复杂          |
| 适用场景   | 服务器推送、实时通知    | 实时交互、游戏    |
